# 因果連鎖分析

出典は小野義之さん（AGC、滋賀大学データサイエンス学部の社会人講師）のサイト
<https://causal-chain.com/> と note（<https://note.com/causal_chain_com>）。
2026-10-20に、サイトの全5ページと、手法を扱う記事8本（#02・#03・#04・#06・
#09・#14・#21・#25）を読んでまとめた。本文の写しではなく要点の言い換え。
すばるは河本ゼミ第3回（10/20）でこの講義を受けている。

## 芯になる考え方

- 因果を一本線でなく「面」で見る。一つの結果に原因は複数あり、一つの原因が
  別々の結果を生み、同じ働きかけでも条件しだいで結果が変わる。
- 目の前の出来事をそのまま結論にしない。「売上が落ちた→営業を強化」のような
  一足飛びを疑い、間にあるはずの要因（潜在因子）を探す。
- 原因を当てて終わりにしない。実行できる打ち手と、それが効いたかを確かめる
  方法までつなぐ。
- 図を描いても因果は証明されない。図は仮説の地図で、観察・聞き取り・データ・
  施策の結果で直し続ける。
- 出発点は違和感や「こうなってほしい」でよい。問いを重ねるうちに、解くべき
  問題が見えてくる。問題設定そのものがずれていないかも疑う（例：「医師が
  足りない」ではなく「医師が続けて働ける仕組みになっていない」）。

## 5つの共通技能（この順で手を動かす）

1. **原因と結果を両方向にたどる。** 上流の原因と下流の影響へ広げ、見つかった
   要因からまた広げる。要因の間に抜けた段階がないか、結果が原因を強める循環
   （自己強化ループ）がないかを見る。
2. **条件・例外・別の経路を探す。** その説明が成り立つ条件と、成り立たない
   場合の違いを調べる。同じ結果に至る別ルートと、目的を実現する別の手段も
   挙げる。
3. **暗黙知と潜在因子を引き出す。** 発言やデータに出ていない判断基準、価値観、
   不安、実行の障害を探す。具体例や仮説をぶつけて、本人も言葉にしていない
   知識を引き出す。
4. **因果構造を図にする。** 関係者が同じ図を見て話せるようにする。確認済みの
   事実と未確認の仮説を分け、説明の飛躍と足りない情報を点検する。
5. **介入点と観測点を組にする。** どこに働きかけるかと、効果を何で確かめるかを
   一緒に決める。効かなければ、別の障害や成立条件を調べて仮説を直す。

## 問いのチェックリスト（「他には？」と言える状態にする）

A→Bを見つけたら、そこで止めずに順に問う。

- AならBは必ず起きるか。起きない場合は何が違うか。
- AとBの間に、別の段階はないか（飛躍していないか）。
- Bを妨げる条件はないか。Aを通らずにBに至る道はないか。
- Aのさらに上流は何か。Bのその先に何が起きるか（二次・三次の影響）。
- 結果がまた原因を強める循環はないか。
- その打ち手は必ず効くか。効かない場合は何が違うか。副作用はないか。短期で
  効いて長期で悪化しないか。
- 相関を因果と読んでいないか。因果が逆向きではないか。
- 今あるデータや、残った人だけを見ていないか。辞めた人、断った人、選ばな
  かった人に聞いたか。
- 誰かの我慢や使命感が、壊れた仕組みを支えて見えなくしていないか。
- 過去の施策を正当化したい気持ち（メンツ、つぎ込んだ費用）が、原因の調べ方を
  ゆがめていないか。

## 図の描き方（このワークスペースの決まり）

- Graphviz（DOT）で描く。`graph [rankdir=LR]` で左から右へ流し、右端に結果
  （問題）を置く。
- 工程や結果は四角（`shape=box`）、要因は楕円。同じ文言の要因が複数あるときは、
  IDを分けて `label` を同じにする。
- 線の区別：実線＝データや事実で確かめた、点線（`style=dashed`）＝推測・未確認、
  灰色（`color=gray55,fontcolor=gray40`）＝確かめて関係なし。凡例を
  `shape=note` で入れる。
- データ分析の前には「データ存在確認」で要因に色を付ける。青＝今あるデータ、
  緑＝今はないが頑張れば取れる、白＝取れそうもない、赤＝ビジネス効果がある
  もの・意思決定に使うもの。青や緑が赤につながる経路の上にあるかを確かめる。
  緑は「取れるかもしれない」という判定で、取るかどうかは判断への役立ち方と
  手間で決める。必要な緑は、分析に使える項目（特徴量）として定義する。
- 両方を1枚に描くときは、データの有無を楕円の塗り（青 `#D6E8FA`、緑
  `#D9F0D3`、白）で、確かめたかどうかを枠線（実線・点線・灰色）で表す。
  判断に使う指標は太い赤枠（`penwidth=2.5,color="#C0392B"`）、意思決定に
  使う結果は赤く塗った四角にする。
- 介入点は六角形（`shape=hexagon`）で、最後の行に「観測：…」と観測点を書く。
  働きかける先へオレンジの矢印（`color=darkorange`）を引き、判断材料に使う
  指標からは点線のオレンジで介入点へつなぐ。
- 授業の演習は viz-js.com（Web版のGraphviz）を使う。戻る・進む・再読み込みで
  入力が消えるので、先にテキストをファイルに保存する。
- viz-js.com の入力欄はコードエディタで、`{` を打つと閉じかっこが自動で入る。
  全文を打ち込んだあと、末尾に余分な `}` が1つ残るので消す。日本語の幅を測れず
  四角から文字がはみ出すので、四角には `width` を指定する。
- ファイルに書き出すときは、手元のGraphvizで日本語フォントを指定する。

  ```bash
  dot -Gfontname="Hiragino Sans" -Nfontname="Hiragino Sans" -Efontname="Hiragino Sans" -Tpdf 図.txt -o 図.pdf
  ```

  SVGなら `-Tpdf` を `-Tsvg` にする。

作った例（どちらも `~/河本ゼミ/秋_JX金属/` の下）：

- ラーメンの要因解析（第3回の演習）：`配布資料_1020/ラーメン因果連鎖_全部入り案.txt`
- JX金属のめっき付着量不良：`めっき因果連鎖_案_1020.txt`（同じ名前のPDF・SVGあり）

## 3つの応用領域

課題に合わせて組み合わせ、新しい要因が見つかったら図と問いに戻る。

### データサイエンス

今あるデータから分析を始めない。先に「何を判断したいか」と、それに関わる因果を
描く。データ存在確認で足りない情報を見つけ、観察・聞き取り・アンケート・記録の
見直しで取れないかを考える。

### 問題解決

- **GAP分析：** Goal（目的）・Activity（必要な活動）・Problem（妨げ）・
  Neutral observation（どれにも属さない事実や外乱）で整理する。「それは何の
  ため？」と上の目的へさかのぼると、手段を目的と取り違えていたことや、別の
  活動に気づける。
- **人の理解汎用モデル：** 人は受け取った情報を価値観で解釈し、意思を持ち、
  条件を比べて判断し、行動する。「やりたいと思っていない」のか「やりたいのに
  できない」のかを分ける。
- **高度アンケート設計：** 理由の違いを見分けられる設問にする。単一選択の
  「得意科目」のような自己申告ラベルは、能力ではなく選び方を測っていることが
  ある。複数選択にする、間の段階（進路の希望、実際の配属など）も聞く、「何が
  違えば残りましたか」と聞く。分析は単純な平均の比較でなく、条件付きで見る
  （ベイジアンネットワークなど）。

### 生成AIとの対話

- AIは聞かれた範囲で答える（「聞かれませんでしたから問題」）。一本線の答えが
  返ったら、面に広げて問い直す。
- 追加で聞き直すより、最初の問いを書き換える方がよいことがある。例：「Aの原因は
  B？それともCやD？その背後に別の要因は？それぞれの対策と副作用は？」
- こちらの仮説は粗くてよい。AIが引っ張られすぎないよう、断定せずに出す。
- AIが挙げた要因は事実とみなさず、元の発言・資料・現場と照らして確かめる。
  AIはもっともらしい因果を速く作れてしまう（飛躍、抜けた段階、逆向きの因果、
  相関の取り違え）。

## 意思決定三原則（判断をAIに任せる、または判断の仕方を設計するとき）

目的に加えて、①判断に必要な要因、②影響範囲（どこまで、いつまで、何次の影響
まで）、③制約条件（してはいけないこと）を与える。範囲が狭いと、性能の高いAI
ほど局所最適を突き詰める。

## このワークスペースでの動き方

- 「なぜ」「原因」「打ち手」を聞かれたら、一本線で答えない。直接の原因、背景、
  構造的な要因、見落としやすい要因、打ち手と副作用、介入点と観測点に分けて
  考える。
- 事実と推測を分けて書き、推測には推測と書く。
- 図にするときは上の決まりで DOT を書き、ファイルに保存してから表示・書き出し
  する。
- 他の人の説明やAIの答えを点検するときは、問いのチェックリストを順に当てる。
