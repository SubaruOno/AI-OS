# wbsc-collect（WBSCの試合データとU-23スタッフ共有サイト）

U-23W杯の対戦相手分析のために、WBSCの大会サイトから試合データを落とす道具です。
同じデータから、日本代表スタッフ向けの共有サイトも組み立てます。
何のために集めているかは [スカウティング準備](../private/u23-scouting-prep.md) にあります。

場所は [apps/wbsc-collect/collect.py](../apps/wbsc-collect/collect.py) とその隣のファイル。
Python 3 の標準ライブラリだけで動き、追加のインストールは要りません（サイトの公開だけ wrangler を使います）。

## 仕組み

WBSCの大会サイト（`wbsc.org` と各大陸連盟の `wbscamericas.org`、`wbscasia.org`、
`wbsceurope.org`）は Inertia.js で作られていて、**HTMLの `<div data-page="...">` に
描画用のJSONがそのまま入っています。** 画面を読み取るのではなく、このJSONを取り出します。
そのため画面の見た目が変わっても壊れにくく、画面に出ていない項目まで取れます。

大会ごとに違うのはドメインとスラッグだけなので、スクリプト上部の `EVENTS` に1行足せば
新しい大会を追加できます。

## 使い方

```bash
python3 apps/wbsc-collect/collect.py --list
python3 apps/wbsc-collect/collect.py --event u23-americas-2025
python3 apps/wbsc-collect/collect.py --all
```

日程と結果の一覧（`games.json`）は毎回取り直します。試合ごとの生データ（`raw/`）を使い回すのは、
終わった試合（`gamestatustext` が `F` で始まる。`F/7` のようなコールドも含む）で、
ボックススコアが空でないものだけです。試合中や試合前に取ったデータは `raw/` に残さず、
次に流したときにまた取り直します。

日程の上でまだ始まっていない試合（状態が空で、開始時刻が今より後）は、取っても中身が空なので取りに行きません。
開始時刻を過ぎても状態が変わらない試合は、遅れや中断のこともあるので取りに行きます。
開始時刻（`utc` 列）は今の `-06:00` の形のほか、`Z` や `+00:00` の形で来ても読めます。
サイトの側でも、現地時刻（UTC−6）に直してから日付を決めるので、形が変わっても現地の日付はずれません。

試合を1件取るごとに1秒待ちます（`SLEEP_SECONDS`）。大会中は流すたびに試合中の試合を取り直すので、
WBSCへのアクセスを増やしすぎないよう、この待ちは残してください。1試合あたり1MB前後あります。
読み込みが途中で切れたときと、WBSC側の不調（HTTPの5xx）のときは、間隔を空けて合わせて4回まで試します。
404のように「ない」と返ってきたものは、やり直しても変わらないので1回でやめます。
打者・投手・1球ごとのCSVの `date` 列が空のときは、`games.json` の開始時刻（現地）の日付で埋めます。

出力先は `~/野球/U23ワールドカップ2026/05_収集データ/<大会キー>/`。
**選手データなのでこのリポジトリには入れません。**

| ファイル | 中身 |
|---|---|
| `games.json` | 日程と結果の一覧。毎回取り直し、CSVを書き終えてから最後に書く |
| `raw/<試合ID>.json` | 試合ごとの生データ。終わった試合だけ残る |
| `batting.csv` | 打者成績。1行が1試合1選手 |
| `pitching.csv` | 投手成績。`spot` が90の枠 |
| `plays.csv` | 1球ごとの記録。打席の結果はその打席の最後の行に入る。`half` は表が `top`、裏が `bot`。`batter_bats` と `pitcher_throws` に打者と投手の左右 |

10月4日の大会前に取った `u23-wc-2026` の `raw/` 30件は、中身が空のまま使い回される状態だったので、
10月16日にゴミ箱へ移しました。

### 取り込みが止まるとき

途中で止まっても `games.json` とCSVの中身が食い違わないよう、次のときは何も書かずに「止めました:」と理由を出し、
終了コード1で終わります。前回の取り込み結果はそのまま残ります。

- 日程が0件で返ってきた（WBSCのページの形が変わった、読み込みに失敗した、など）
- 日程の試合が、前回の `games.json` より減った
- 終わった試合の読み込みが、やり直しても通信の失敗で取れなかった。電波のよい所で流し直します

日程が減ったのが意図したものなら、`--allow-fewer` を付けて流すと通ります。0件のときは、これを付けても止まります。
大会中に update_site.sh から流すときは、`--force` を付ければこれが付きます（下の「大会中の更新」）。

```bash
python3 apps/wbsc-collect/collect.py --event u23-wc-2026 --allow-fewer
```

試合中の試合が取れなかったときは止まらず、注意を出して次へ進みます。その試合の途中の成績は入りません。
`games.json` はCSVを書き終えてから最後に書くので、CSVの途中で止まっても前回の組が残ります。

打者・投手・1球ごとのCSVのどれかが0行になったときは、前回のCSVを `/usr/bin/trash` でゴミ箱へ送り、
「0行のため、前回の○○をゴミ箱へ送りました」と1行出します。古い成績が残って、サイトに読まれないようにするためです。
0行のCSVを先に片付けるので、ゴミ箱へ送れずに止まったときは、まだ何も書いていません。

**終わった試合でも、WBSCが404か5xx（4回試したあと）を返したときは、止まらずにその試合を飛ばします。**
そのまま `games.json` とCSVを書くので、日程では「終了」なのに、その試合の成績の行がない状態になります。
`raw/` には残らないので、次に流したときに取り直されます。止める形にはまだ直していません。

### 裏の攻撃が抜けていた件（2026-10-16に修正）

10月16日まで、collect.py は回の裏の記録を読んでいませんでした。WBSCの生データでは裏のキーが `bot` なのに、
`bottom` を探していたためです。`plays.csv` には表の攻撃しか入らず、各チームの打球は先攻で戦った試合の分だけでした。

直したあと、手元の `raw/` から5大会を作り直しました（通信はしていません）。
2024年W杯の打球の記録は970件から1927件に増えています。打球図、打者表の打球・ゴロ率・フライ率・引っ張り率・流し率、
チームのゴロ率・フライ率は、10月4日に公開した第1版のサイトや、9月に書き出した対戦相手.html と数字が変わりました。
古い数字を写したメモや、スタッフに見せた傾向があれば、作り直した数字で見直してください。

## 取れるもの

`plays.csv` には画面に出ていない項目が入っています。

- **`pitchheight` / `pitchoutside`** … 1球ごとの到達位置の座標。
  ストライクゾーン上にプロットできます
- `pitch_pitches` / `pitch_balls` / `pitch_strikes` … その行が1球か、ボールかストライクか（1球の行は1）。
  足せば打席や投手ごとの球数になります
- `balls` / `strikes` / `outs` と各塁の走者、進塁と刺殺
- `result` 系と `hittype` … 打球の種類と処理した野手

`pitching.csv` は投球回・被安打・自責点に加えて、`pitch_pitches`（総球数）、
`pitch_strikes`、`pitch_ground` と `pitch_fly`（ゴロとフライの数）まで入ります。

**そして1球ごとに `utctimestamp` が入っています。** `gameData.gamevideo` に
GameTimeの試合映像のURLが入るので、**この2つを突き合わせれば、打席の頭出しリストを
自動で作れます。** 映像URLの有無は大会によって違います（2024年W杯は50試合すべて、
欧州選手権は20試合すべて、北中米カリブ予選は24試合中12試合、アジア選手権は0件）。

打球には `hitdistance`（距離）、`hitpull`（打球方向の角度。0が中堅、負が左方向）、`hitlaunch`（打球角度）が
入ります。全打席ではなく、記録された打球のみです（2024年W杯で1927件）。
`exitvelo` の枠はありますが値は空でした。

**`hitdistance` は実際の飛距離ではなく、WBSCの記録アプリの図の上の距離と見ています。**
10月16日に5大会6675球で調べた見立てです。柵越えの本塁打は257〜314に入り、82本中37本がちょうど310でした
（310が入力の上限と見られます）。内野ゴロは94〜113、外野フライは226に集まります。
メートルではありえず、フィートとしても柵や外野手の位置が2割ほど近すぎます。
打球の約半分は、処理した野手の定位置の距離（94・113・179・226など）で記録されています。
WBSCの資料で単位を確かめたわけではありません。打球図はこの値をそのまま距離に使い、図の下に同じ注意を書いています。

**入っていないもの**は `speed`（球速。全部ゼロ）、`pitchtype`（球種。-1で未分類）、
`hitx` / `hity`（ゼロ。打球の位置は `hitpull` と `hitdistance` の極座標で出します）。
球速と球種はTrackmanとBLASTの自前計測で埋める前提になります。

## レポートの書き出し

[build_report.py](../apps/wbsc-collect/build_report.py) が、集めたCSVから
相手11カ国分の1枚のHTMLを作ります。

```bash
python3 apps/wbsc-collect/build_report.py
open ~/野球/U23ワールドカップ2026/06_レポート/対戦相手.html
```

**外部のCSSもJavaScriptも読み込まない単体ファイルです。** 通信が切れていても開けるので、
現地でそのまま使えます。国のタブで切り替え、表の見出しを押すと並べ替わります。

中身は相手ごと・大会ごとに、チームの傾向（犠打、盗塁、四球率、三振率、ゴロ率、
フライ率）、打球の散らばり図、打者の表、投手の表。

打球の散らばり図は `hitpull` と `hitdistance` から位置を出しています。縮尺は全図で同じで、
距離100・200・300の点線を引いています。フェアの範囲（±45°）の外と、距離0以下の打球は描きません。
種類は色と形の両方で分けています（ゴロ●・ライナー▲・フライ■・ポップ◆）。
`hittype` の 1〜4 が何を指すかは `narrative` と突き合わせて確かめました。

引っ張り・流しは打者の左右で数えます。左打ちは右方向が引っ張りで、両打ちは相手投手の投げ手と逆の打席に
立ったと見なし、左右が分からない打者は数えません。出塁率の分母は打数＋四球＋死球＋犠飛で、
投球回は野球の表記（9回1/3は `9.1`）です。打率・出塁率・防御率などの端数は四捨五入です（5/16 は .313）。
打球のデータがない大会は、チームのゴロ率・フライ率を「.00」ではなく「-」と出します。
大会の途中で名前の綴りが変わった選手は、一番新しい試合の綴りで出します。

どの相手にどの大会を見せるかは、スクリプト上部の `OPPONENTS` で決めています。

## スタッフ共有サイト（build_site.py）

U-23W杯2026（ニカラグア、現地11/6〜15）の日本代表スタッフと共有するサイトを、収集データと
手で整えた今大会の情報から組み立てます。静的なHTMLを Cloudflare Pages に上げる形です。
第2版は2026年10月16日に作り、10月17日に4方向の点検と仕上げをしました。何をどう決めたかは [第2版の計画](../plans/2026-10-16-u23-site-v2.md) にあります。

時刻はどのページも日本時間を太字で先に出し、現地時刻（UTC−6、夏時間なし。日本の15時間遅れ）を小さく添えます。
「今日の試合」だけは現地の日付で選びます。

### ページの構成

ヘッダーの行き先は 日本・日程・相手国・大会方式 の4つです。URLはフォルダ形式で、`team/cuba/` の中身は
`team/cuba/index.html` です。Cloudflare Pages が `.html` を拡張子なしへ308で転送するので、その往復をなくしています。
第2版は2026年10月17日に公開しました。入口のリンク（`<合言葉>/index.html` と `<合言葉>/`）は今までどおり開きますが、
第1版の `team/cuba.html` のような個別ページのリンクは404（白紙）になります。

| URL（合言葉のフォルダの下） | 中身 |
|---|---|
| トップ | 次の日本戦（残り時間・「試合中」・「終了」を開いた端末で計算。下に書く）、前の日本戦の結果、今日の試合、日本戦の一覧（先攻・後攻、球場と町）、順位表（日本のB組が先）、相手国の入口、全ページ保存のボタン、WBSCの公式ページへのリンク |
| `schedule/` | 全試合の日程と結果。見出しは日本の日付で「11/7(土)　現地 11/6(金)」の形。対戦は日本戦も先攻・後攻の順に並べ、日本は太字と○●で目立たせて「日本は後攻」のように添える。相手の決まっていない試合は「未定」（日本の相手だけ未定なら「日本 vs 未定」）。区分の札（1次R・SR・順位決定・3位決定・決勝）、WBSCのボックススコアと映像へのリンク。開くと今日（現地）の見出しまで送る |
| `teams/` | 相手国11カ国の一覧。B組が先 |
| `team/<国>/` | 監督・首脳陣・世界ランク・出場経路・直近の成績（出典つき）、今大会の名簿（韓国と台湾は読みと所属の日本語名つき）、注目選手、日本との対戦（参考値）、今大会の試合（日本戦の行は「● 日本 1-6 韓国」「日本は後攻」のように日本から見た形）と登板記録・成績・打球図、大会ごとの傾向、過去の大会（最新だけ開いた折りたたみ）。選手の表は「今大会に出られる選手だけ」が最初からオン |
| `japan/` | 公式発表の24人（背番号順と守備別。守備別の4つの表は列の位置をそろえている）、首脳陣、日本戦の日程と結果。大会が始まれば日本の打者・投手の表と登板記録も出る |
| `format/` | 大会の流れ、スーパーラウンドの持ち越し、日本の順位ごとの相手、3球場と町、規定、直前合宿（公式発表の範囲） |
| `p/<鍵>/` | 選手ページ。大会ごとに違う playerid を、名前・生年・国から作った鍵で1人1ページにまとめる。鍵では1人にならない組は、[サイト用/同一人物.csv](../../野球/U23ワールドカップ2026/07_出場選手情報/サイト用/同一人物.csv) で結ぶ。名前は一番新しい試合の綴りで、守備はWBSCに登録された「登録守備」。2002年以前の生まれ（今大会に出られない）の選手はページを作らず、表の名前もリンクにしない。日本の選手は大会が始まってから作り、生年は載せない |
| `offline/` | 端末に保存していないページを電波なしで開いたときに出る |

トップの次の日本戦は、「今日／明日」ではなく残り時間で出します。日本と現地で日付がずれ、現地の朝は日本の夜なので、
「今日」がどちらの今日か分からなくなるためです。表示は「あと4時間」「あと1日8時間」「あと21日」のようになり、
3日以上は日数だけ、1時間を切ると分だけです。日時そのものは、すぐ下に日本時間と現地の両方が出ます。
開始から4時間は「試合中」と出します。4時間を過ぎても結果の入らない試合は飛ばして次の日本戦を出し、
残りがなければ「終了（結果は次の更新で入ります）」です。ページを開いたままでも1分ごとに進みます。

点数は、先攻・後攻の両方がそろうまで「-」と出します。記録された0は「0-0」のまま出ます。
終了なのに点数が入っていない試合は○●を付けず、順位表にも数えません（0-0の引き分けとは扱いません）。

13行以上ある選手の表（日本代表の24人の表を含む）は、表の中で縦にスクロールし、見出し行が上に残ります。
スマホの横向きなど高さ600px未満の画面では、表の中の縦スクロールをやめているので、見出し行は残りません。
ページ内リンクの帯が画面の上に残るのは、幅700px以上・高さ600px以上の画面だけです。

順位表は、WBSCのW杯共通の規程（2024年版）にある同率の決め方で計算します。勝率で並べ、2チームが並べば直接対決、
3チーム以上なら当該チーム同士の勝敗、それでも並べば当該チーム同士のTQBです。スーパーラウンドが始まると、
持ち越し込みの表を上に出します。2026年大会の要項そのものはまだ見ていないので、大会方式のページでは
イニング数・タイブレーク・コールド・同率の決め方を「未確認（大会要項で確認中）」と書いています。

### 組み立てと公開

```bash
cd apps/wbsc-collect
python3 build_site.py                   # 組み立てだけ。既定の dist に書き出す
python3 build_site.py --out DIR         # 書き出し先を変える（update_site.sh は dist.new を使う）
python3 build_site.py --data-root DIR   # 収集データの場所を変える（ダミーで試すとき）
sh deploy_site.sh [フォルダ]             # Cloudflare Pages に上げる。省略時は dist
```

ふだんは下の update_site.sh を使い、この2つを直接は動かしません。

build_site.py は、計算を [site_logic.py](../apps/wbsc-collect/site_logic.py)（試合の状態と時刻、順位、持ち越し、
日本から見た勝敗、登板記録、選手の鍵）に、電波対策を [site_offline.py](../apps/wbsc-collect/site_offline.py) に任せます。
表と打球図は build_report.py の部品をそのまま使います。書き出し先は `~/野球/U23ワールドカップ2026/07_サイト/dist/` で、
全ページを作り終えてから `--out` のフォルダだけを作り直します。古い中身は `/usr/bin/trash` でゴミ箱へ送ります。
収集データの `games.json` が空か読めないときは、空の日程を書き出さないよう、組み立ての前に止まります。

`--out` で作り直すのは、次のどれかに当たるフォルダだけです。

- 空のフォルダか、まだないフォルダ
- 根元に目印の空ファイル `.u23-site` があるフォルダ。build_site.py が書き出すたびに置きます
- 目印を付ける前の build_site.py の出力と同じ形のフォルダ（根元が index.html・404.html・robots.txt・_headers と、合言葉のフォルダ1つだけ）

ほかのフォルダを渡すと「build_site.py の出力に見えないので消しません」と出して止まり、中身には触れません。
robots.txt があるだけでは通しません（Webアプリの public/ にもふつうにあるため）。ホーム、リポジトリ、

### 合言葉と、載せないもの

**リンクを知っている人だけが開ける形です。** ページはすべて、推測できない24文字の合言葉の

残したまま `update_site.sh --rollback` を流すと、古いリンクがまた開きます。

リンクが漏れれば相手チームにも渡るものとして扱い、次は載せません。線引きの全文は
[第2版の計画](../plans/2026-10-16-u23-site-v2.md) の「サイトに載せないもの」にあります。

### 大会中の更新（update_site.sh）

大会中は [update_site.sh](../apps/wbsc-collect/update_site.sh) 1本で更新します。途中のどこかで失敗したら、そこで止まります。

```bash
cd apps/wbsc-collect
sh update_site.sh              # 普通の更新
sh update_site.sh --no-deploy  # 入れ替えまでで止め、公開しない
sh update_site.sh --rollback   # 1つ前の版に戻して上げ直す。もう一度で元に戻る
sh update_site.sh --force      # 日程の試合数・ページ数・終了試合数が減っても止めない
```

普通の更新は次の順に進みます。

1. 取り込み（`collect.py --event u23-wc-2026`）
2. 組み立て（`build_site.py --out dist.new`）
3. 検査。日程の試合が0件でない、トップに「日本戦」の文字がある、日程の試合数・ページ数・終わった試合の数が前回の `dist` より減っていない（数は `status.js` と `pages.json` から読む。今の `dist` に `pages.json` がなければ、前回との比べは飛ばす）
4. 入れ替え。今の `dist` を `dist.prev` に、`dist.new` を `dist` にする（それまでの `dist.prev` はゴミ箱へ）
5. 公開（`deploy_site.sh`）
6. グループに貼る1行を表示

最後の1行は「U-23サイトを更新しました（日本時間 11/9 14:10）。現地11/8の6試合の結果まで入っています。」の形です。
その日の試合が途中なら「現地11/9は6試合中1試合の結果まで入っています。」になります。
**スタッフのグループには、すばるが手でコピーして貼ります。** 自動では送りません。
取り込み・組み立て・公開にかかった秒数も出ます。

`--no-deploy` は、電波が弱くて公開を後に回したいときや、先に画面を確かめたいときに使います。
手元の `dist` は新しい版に入れ替わるので、上げるときは `sh deploy_site.sh` を流し、表示された1行を貼ります。

`--rollback` は `dist` と `dist.prev` を入れ替えて上げ直します。もう一度流すと元に戻ります。
`--no-deploy` と一緒に付ければ、入れ替えだけをして公開はしません。

`--force` は、日程の試合数・ページ数・終わった試合の数が意図して減ったときに検査を通すためのものです。
取り込みにも `--allow-fewer` が付くので、collect.py の「日程の試合が前回より減った」も通ります（上の「取り込みが止まるとき」）。
日程が0件のときは、`--force` を付けても止まります。終わった試合が減ったときは、先に取り込みを疑ってください。

止まったときは「止まりました（○○の段）。」と、公開中のサイトと手元の `dist` がどうなっているかが出ます。
途中で Ctrl-C を押したときや、ターミナルを閉じたときも、同じ案内を通ってから終わります。
入れ替えと戻すの段では、そのとき実際にあるフォルダ（`dist`・`dist.prev`・`dist.new`・`dist.swap` のうち、あるもの）も並べます。

| 止まった段 | 公開中のサイトと手元 | 次にすること |
|---|---|---|
| 取り込み | どちらも前のまま。collect.py が「止めました:」と出したときは、収集データも前回のまま | 理由の行を読む。日程が減ったのが意図したものなら `--force`。通信の失敗なら電波のよい所で流し直す |
| 組み立て | どちらも前のまま | 上に出たエラーを見て直し、流し直す。`games.json` が空か読めないときもここで止まる |
| 検査 | どちらも前のまま。組み立てた版は `dist.new` に残る | 理由の行（日程が0件、ページ数が減った、など）を読む。意図して減らしたものなら `--force` |
| 入れ替え | 新しい版を置く前に止まったら、前の版を自動で `dist` に戻すので、どちらも前のまま。組み立てた版は `dist.new` に残る | 並んだフォルダを確かめて流し直す。「dist がない状態です」と出たら、案内どおりに `dist.prev` か `dist.new` の名前を `dist` に変える |
| 公開 | 手元の `dist` は新しい版、公開中は前の版 | 電波のある所で `sh deploy_site.sh` を流す |
| 戻す | `dist` を脇へ動かした直後に止まったら、元の版を自動で `dist` に戻す。1つ前の版を置き終えたあとなら `dist` は1つ前の版で、元の版は `dist.swap` に残る。公開中は前のまま | 出た文と並んだフォルダを読む。「dist がない状態です」と出たら、案内どおりに `dist.swap` か `dist.prev` の名前を `dist` に変える |

公開の段で止まったら、`update_site.sh` をもう一度流す前に `sh deploy_site.sh` で上げ直してください。
先に流し直すと、まだ公開していない版が `dist.prev` に入り、そのあとの `--rollback` で公開中だった版に戻れなくなります。

### 電波が弱いとき

球場やホテルの回線は確かめられていないので、端末に保存して読める作りにしています。
スタッフには、最初に次の2つを頼んでください。

- iPhone は Safari でリンクを開き、共有ボタンから「ホーム画面に追加」して、そこから開く
- ホテルのWi-Fiなど電波のよい所で、トップの「全ページを端末に保存」を押す（ボタンの下に進み具合が出て、最後に「保存しました（○/○ ページ）」になります）

最初に開いたときに、トップ・日程・相手国一覧・相手国の全ページ・日本・大会方式は自動で保存されます。
選手ページは、全ページ保存を押すか、一度開いたものだけが残ります。

読み込みは、3秒待ってネットの返事がなければ保存した版を出し、裏で新しい版を取りにいきます。
ヘッダーの下の帯には、ふだんは「最終更新 日本○／現地○」と「結果反映」が出ます。「結果反映」は、最後に試合が終わった日の
第1試合から続けて終わっていれば「現地11/7 第6試合まで」、途中に終わっていない試合があれば「現地11/7 6試合中5試合」の形です。
結果がまだ1つもなければ「まだ試合はありません」と出ます。
保存した版を出しているときは「電波が弱いため（電波がないため）保存した内容を表示中」と、保存した時刻が出ます。
裏で新しい版が取れると「新しい更新があります（押すと再読み込み）」に変わります。
保存していないページを電波なしで開くと、`offline/` の「電波がないため開けません」が出ます。

LINEのトークのリンクから開くと、LINEの中のブラウザでは保存が効かない可能性があります。
iOS のアプリ内ブラウザでは Service Worker が動かないことがあるためで、実機ではまだ試していません。
LINEで受け取ったら Safari で開き直すよう案内してください。サイトのトップと電波なしの画面にも、
「LINEなどアプリの中で開くと、保存が効かないことがあります。」と、言い切らない形で書いています。
Safari は、7日間開かなかったサイトの保存データを消すことがあります。ホーム画面に追加したものは対象外です。

### 確かめ方

手元では [.claude/launch.json](../.claude/launch.json) の `u23-site` で、`dist` を http://localhost:8781/<合言葉>/ で開けます。
Python の簡易サーバーなので、Cloudflare の `Cache-Control` や308の転送は再現しません。

URLの末尾に `?now=2026-11-08T12:00:00-06:00` のように現地の時刻（時差つき）を付けると、「今」を差し替えて開けます。
次の日本戦の出し分け（残り時間・試合中・終了）、今日の試合、日程の自動スクロールを大会前でも確かめられます。

大会中の表示（試合中・終了・スーパーラウンドの表）は、ダミーの収集データで確かめます。
`05_収集データ` と同じ形（大会キーごとのフォルダ）のダミーを作り、`--data-root` で渡します。
本物の `dist` を上書きしないよう、書き出し先も別にしてください。

```bash
python3 build_site.py --data-root <ダミーのフォルダ> --out <試し用の書き出し先>
```

10月16日の試しでは、2024年大会の結果を2026年の日程にはめたダミー（終了・試合中・スーパーラウンド・相手未定のメダル戦を含む）を使いました。
これを作る台本は作業用の一時フォルダに置いたままで、リポジトリには入っていません。
10月17日の仕上げでも同じダミーと本物の `dist` で、全ページのリンク切れ、headless Chrome で全ページを開いたときのエラーと横へのはみ出し、
電波なしの動きを確かめています。そのための台本（リンク切れの点検、headless Chrome の試しと画面写真）も一時フォルダにあり、リポジトリには入っていません。

計算と電波対策の部品は、それぞれ自分で照合できます。

```bash
python3 site_logic.py --selftest    # 2022年・2024年の公式順位（持ち越し込み）、日本戦の勝敗、登板記録、選手の鍵と照らし合わせる。最後に「合わなかった 0件」
python3 site_offline.py --selftest  # 一時フォルダに sw.js などを書き出して中身を確かめる。最後に「selftest: OK」
```

update_site.sh は、環境変数 `U23_SITE_DIR`（dist を置くフォルダ）と `U23_COLLECT`・`U23_BUILD`・`U23_DEPLOY`（各段のコマンド）で
中身を差し替えて試せます。`--no-deploy` を付ければ公開はしません。`U23_COLLECT` を差し替えたときは、`--force` を付けても
取り込みに `--allow-fewer` は足されません。10月17日には、入れ替えの途中で失敗したとき、戻すのにも失敗したとき、Ctrl-C で止めたとき、
`--rollback` の途中で失敗したとき、公開に失敗したときの案内と戻り方を、sh と zsh の両方で確かめました。

Service Worker の動き（先に保存するページ、3秒で保存版に切り替わること、電波なしの表示）は、Claude のブラウザペインでは
sw.js を取りに行かないため試せませんでした。10月16日は、使い捨てのプロフィールの headless Chrome に、
Cloudflare と同じ `Cache-Control` を付けて配信して確かめています。

10月17日の公開のあと、本番で次を確かめました。フォルダ形式のページは転送なしで200を返し、`_headers` 自体は外から読めず（404）、
`/*/sw.js` の形の規則で sw.js に `Cache-Control: no-cache` が付きます。全ページに `X-Robots-Tag: noindex, nofollow` と
`Referrer-Policy: no-referrer` が付き、ページの中に合言葉は出ていません。`update_site.sh` を通しで流したときの所要時間は、

- iPhone の実機の Safari、機内モード、ホーム画面に追加した状態、LINEの中のブラウザ。出発前に実機で、保存したページと保存していないページの両方を電波なしで開いてください。10月17日に iPhone 17 Pro のシミュレーターの Safari で、縦向きの表示とダークモードだけは確かめました（横向きは Chrome の 812x375 で確認）
- 試合中・中断のときの `gamestatustext` の値。今は推測で「試合中」と「その他」を分けているので、大会初日に実際の値を見て調整が要ります
- スーパーラウンドの組み合わせが日程に載るときの表記（相手が決まるまで仮の名前が入るか）
- 2026年大会の要項（イニング数・タイブレーク・コールド・同率の決め方）。順位はW杯共通の規程で計算しています

### 分かっていて、まだ直していないこと

第2版の点検（10月16〜17日）で見つかり、軽いものとして残したものです。

- 終わった試合が404か5xx で取れないとき、collect.py は止まらずに飛ばします（上の「取り込みが止まるとき」）
- 1次ラウンドの試合が中止（`CANC` など）のまま日程に残ると、スーパーラウンドの顔ぶれが「決まった」扱いになりません
- `raw/` のない引き分けとサヨナラの試合は、TQB に使う攻撃と守備のイニングを近似で数えます。終わった試合の `raw/` は残るので、ふだんは当たりません
- 知らない `gamestatustext` の文字は「試合中」と扱います（上の「まだ確かめていないこと」の3つ目）
- データから来る文字列のうち、エスケープしていない所と、ページに埋め込むJSONと外部リンクの守りが一部足りない所があります
