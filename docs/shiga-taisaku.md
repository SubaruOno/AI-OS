# 滋賀大 対策資料づくり（大阪ガス形式）

京滋リーグの対戦相手の野手対策を、大阪ガスで使っている資料と同じ形で作る道具。
大阪ガスの `~/大阪ガス/分析ツール` をコピーし、滋賀大のデータ向けに直したもの。
大阪ガス側の道具には手を入れていない。

- 道具: `~/野球/対策資料/滋賀大ツール/`
- 資料の置き場: `~/野球/対策資料/<年と季節>/<大学名>対策資料/`
- 元データ: 野球部OneDriveの全試合Excel（例: `令和8年秋季リーグ戦_Ⅱ部_全試合.xlsx`）。
  このMacにはOneDriveが同期されていないので、すばるがWebから `~/Downloads` に落とす

選手データはチーム内部のものなので、AI-OSのリポジトリには入れない。

Macアプリ [分析デスク](analysis-desk.md) でも、チームフォルダを開いて分析を画面で見て、
`コメント.yaml`・`投手コメント.yaml` を書き、`build_v2.py` などを書き出しボタンから呼べる（2026年10月9日から）。
なお `convert_shiga.py` は振り逃げを打席の終わりに数えていないので、振り逃げがある打者は成績CSVの打席が1つ少ない。

## 全体の流れ

1回分の対策資料は、次の順で作る。各段階の詳しい手順は下の節にある。

1. 元データを受け取る。全試合Excel（今季・前の期）をすばるが `~/Downloads` に落とす
2. データを点検する（[入力データの点検](#入力データの点検)）。名前の表記ゆれ・左右・カウント・球速を見て、直すものを決める
3. `convert_shiga.py` で相手チームのデータに変換する。`config.yaml` の `pitchers`・`pitchers_short`・`forms` を書き戻す
4. 分析の数字を出し、分析ページ（HTML）にまとめる（[分析とコメントの書き方](#分析とコメントの書き方)）
5. コメントを書く。まず1人分（打者・投手それぞれ）を見せ、形が決まってから全員分
6. 打者対策（`build_v2.py`）と投手対策（`build_pitcher_shiga.py`）を作る
7. PowerPointで開いて全ページを画像で確認し、PDFに書き出す。投げ方・プレートの位置はすばるが資料に書き込み、`forms` に写す
8. 必要なら自チームの分析（[自チームの分析](#自チームの分析)）を足す
9. 監督に送る（[監督への送付](#監督への送付)）
10. ledger に記録し、京都外大の回のような引き継ぎメモを `private/` に残す


```bash
cd ~/野球/対策資料/2026秋/京都外国語大学対策資料 && python3 ~/野球/対策資料/滋賀大ツール/build_v2.py .
```


1本目がExcelを大阪ガス形式に変換し、2本目が図の作成から資料の組み立てまでを通す。
3本目は打線の一枚まとめ（Excel）。できるのは `output/<大学名>_対策資料_v2.pptx` と
`<大学名>_野手一枚まとめ資料.xlsx`。

資料は大阪ガスの最新形式（v2、三菱重工East 2026年9月3日版）と同じ構成にしている。

1. 表紙
2. 分析対象試合（スコアつき）と作戦の表（回数・成功率・状況・カウント・仕掛けてくる人）
3. 打者ごと、スタメン順→控えは打席の多い順。1ページ目は成績表と図とコメント欄、
   2ページ目はv2データスライド、3ページ目はカウント別配球と滋賀大戦の履歴（15打席未満の控えは1ページ目だけ）

3ページ目は `page3.py` が作る。上半分は初球・打者有利（ボール先行）・中間（0-1、1-1）・追い込み（2ストライク）の
4場面の投球図と、場面ごとのSW率（チーム平均との比較）・空振り・ボール球SW・来た球種。
下半分はチームフォルダの `履歴設定.yaml` に書いた過去の滋賀大戦（2026秋の京都外大では25秋・26春の4試合）の
時期別成績、今季の滋賀大投手陣（今季の全試合Excelから自動で拾う）との対戦、打席の最後の球の図、特徴の1行。
カウント別の図だけを確認用に見たいときは `gen_count_charts.py` で横長のPDFが出る。

1ページ目の図は大阪ガスの 画像貼り付け.py を使わず `build_v2.py` が置く。成績表の下に対右・対左の2段で
投球図（2.05×2.3インチ）と打球方向図（2.8×2.3インチ）、右側に縦の凡例、コメント欄は9.6インチから下。
1ページ目の右上に初球SW率とゾーン内SW率を大きく出し（50%以上は赤、30%未満は紺）、図の下に凡例を貼る。
大阪ガス元の `create_slide2_a4.py` の「Zn内SW」は、ゾーン外の球も含めた全球のスイング率になっている。
滋賀大版の `v2/` のコピーだけ、ゾーン内（X 40〜160 / Y 50〜200）に絞るよう直した（大阪ガス側は未修正）。

コメント欄は「全体：」「対右：」「対左：」「警戒：」の見出しだけ入れて空けておく。
前の期から目立って変わった打者だけ、1行目に「秋：」の行（OPS・三振率・ボール球スイング率・打順の変化から上位2つ）が自動で入る。
v2データスライドは大阪ガスの `~/大阪ガス/scripts/create_slide2_a4.py` を `v2/` にコピーしたもので、中身は変えていない。

一つ前の形式（ミキハウス版のデータスライドと分析まとめPDF）は `run_all.py` で今も作れる。
スタメンは最新試合から自動で入るので、`config.yaml` の `starters` は予想オーダーに合わせて直してよい。

## 投手対策

```bash
cd ~/野球/対策資料/2026秋/京都外国語大学対策資料 && python3 ~/野球/対策資料/滋賀大ツール/build_pitcher_shiga.py .
```

日本生命（2026年8月2日）の投手対策と同じ横長の構成。大阪ガスの `分析ツール/pitcher_analysis` を
`滋賀大ツール/pitcher/` にコピーし、球速の外れ値の範囲を大学Ⅱ部向けにし、グラフのファイル名の食い違いを直した。
載せる投手は `config.yaml` の `pitchers`、3枚だけにする投手は `pitchers_short` に書く（変換し直しても消えない）。

- 表紙・分析対象試合・作戦 → 投手ごとに 紹介・まとめ・球種別統計量・対右/対左成績・対右3枚・対左3枚・滋賀大戦
- 紹介ページに防御率・先発・投球回と牽制（回数・一塁走者時の牽制率・種類・強さ・被盗塁）。投げ方とプレートの位置は、すばるが書いたものを config.yaml の forms に入れる（書いていない投手は見出しごと出さない）
- まとめの1行目に秋の変化（ストレート平均・球種割合・防御率）。2行目以降は大阪ガスの自動下書き
- 防御率は `pitching_record.py` が公認野球規則9.16に沿って自責点を判定する。2026春秋の13試合で、
  投手に付いた失点の合計が最終スコアと、アウトの合計が守備イニング×3と全試合一致することを確認した

## 分析とコメントの書き方

資料に書くコメントは、必ずデータの根拠と、それに基づく提案をセットにする。手順は次のとおり。

1. 分析の数字を出す（道具は `滋賀大ツール/`）
   - `batter_analysis.py`: 打者ごとの選球・打球・球種別・ゾーン別・球速帯（リーグ平均と比べ、Wilsonの95%区間つき）
   - `team_offense.py`: チームの得点パターン（イニング単位。得点はスコアボードの列を正とする）
   - `seq_analysis.py`: 打者ごとの配球の組み立て（初球・途中・追い込み後の球種×コース、前の球→決め球）
   - `pitcher_analysis_shiga.py`・`pitcher_seq.py`: 投手ごとのカウント別配球・位置・決め球・巡目・継投、左右別
2. 分析ページ（HTML）にまとめる。チームフォルダの `分析/make_report.py`・`make_pitcher_report.py` が数字をJSONから読み、文章はスクリプトの中に書く
3. 資料のコメントは YAML に書いて、作るときに読み込む
   - 打者対策: `コメント.yaml`（全体・対右・対左・警戒）。対右・対左は「入り → 途中 → 決め」を1行、根拠は（ ）に1つ
   - 投手対策: `投手コメント.yaml`（各ページ）。「・」の行が根拠、「→」の行が打ち方の提案（赤の太字）。まとめは各ページの要点から
4. 書いた数字は、分析の出力と1つずつ照らし合わせる。数の少ないものは「参考」と書く。推測で書いたことはデータで裏付けたように見せない
5. 画像にして全ページを見る（PowerPointで開き `~/Library/Containers/com.microsoft.Powerpoint/Data/` にPDFで書き出すと許可画面が出ない）

新しい書き方を試すときは、まず1人分（打者なら上羽、投手なら北岡）を見せて、形が決まってから全員に広げる。

## データの点検

- 選手名の表記ゆれは `滋賀大ツール/名前対応表.csv`（入力された表記→正しい表記）で読み込みのたびに直す。
  直したあとも同じチームに似た名前が残っていれば、変換のたびにチームフォルダの `名前チェック.md` と画面に出る。
  2026年9月27日時点で7組を登録（同じシーズン内のゆれが6件あった）。正しい表記は回数の多い方を仮に採用
- 球種名は入力システムの呼び名（チェンジ・カット）をそのまま理解して使う。スローカーブはカーブと別の球として残す
- スローボール・特殊球は投手の集計から外し、紹介ページに「○○あり（n球）」と書く
- 球速は二部なので極端に遅い値もありうるとして、打者対策では除外しない
- 珍しい球種（その投手が5球以下）は映像確認用に一覧を出す（京都外大では `確認リスト_少ない球種.csv`）

## 大阪ガス版との違い

| 項目 | 大阪ガス | 滋賀大版 |
|---|---|---|
| 1球データ・成績CSV | 外部から受け取る | `convert_shiga.py` がExcelから作る（成績は1球データから計算） |
| 投球図・打球方向図 | 外部画像を切り抜く | `gen_images.py` が描く |
| 背番号 | 名前に付いている | データにないので打席数順の仮番号で処理し、仕上げで消す |
| 球速帯 | 143 / 137 で区切る | 125 / 115 で区切る（大学Ⅱ部のストレートは中央値120） |
| 表紙・作戦 | 別に作った画像を貼る | `build_v2.py` がデータから作る |
| 秋の変化 | なし | 各打者のコメント欄の1行目に自動で入る |

座標の決まりは [SHIGABASEの投球コースの座標](shigabase.md) にある。
変換では、滋賀大のゾーン（両軸53.25〜210.75）を大阪ガスのゾーン（X 40〜160 / Y 50〜200）に
軸ごとの比例で換算する。どちらも捕手視点なので左右は入れ替えない。
結果の言葉は `convert_shiga.py` の `RESULT_MAP` で置き換える（見逃し→見送、凡打出塁→凡打 など）。

## 打球方向・守備位置の資料（2026秋 明治国際医療大学の回で追加）

複数期の全試合Excelから相手チームの行だけを取り出して直したCSV（`<チームフォルダ>/clean/<チーム名>_全試合_clean.csv`）を読む。
直し方の記録はチームフォルダの `データ点検.md` に残す。

```bash
cd ~/野球/対策資料/滋賀大ツール && python3 dakyu_jokyo.py <チームフォルダ> <チーム名> <最新期>
```

- `dakyu_macro.py` … 野球部の 分析シート_修正版.xlsm の「打球方向」マクロと同じ描き方（線の種類＝打球の性質、色＝結果、太さ＝強さ）。
  このブックのマクロはMacのExcelでは動かない（開くと修復されてマクロが外れる）ための代わり。マクロは強度を全角「Ａ」で判定しているので、半角のデータでは太さが変わらない
- `dakyu_jokyo.py` … インプレーの図を状況別に8マスずつ並べた選手別PDF（基本の状況、直球の速さ、変化球の球速、最新期とそれ以前の比較）
- `bu_hikaku.py` … 最新期とそれ以前（明治医療では2部と1部）のチーム全体の比較と、打者ごとの表
- `shubi.py` … 守備位置対策の2ページ形式（試作。全員分はまだ作っていない）

球速帯の区切りは `shubi.py` の冒頭にある。

## 直したCSVから作る（2026秋 明治国際医療大学の回で追加）

`convert_shiga.py`・`pitching_record.py`・`履歴設定.yaml` の files は、Excelの代わりに
点検で直したCSVも読める。`ラベル=<…_clean.csv>@<期>` と書くと、CSVの 期 列がその値の行だけを使う。
`試合日` 列があれば、入力が数日に分かれた試合の日付をそれにそろえる。

```bash
python3 ~/野球/対策資料/滋賀大ツール/convert_shiga.py 明治国際医療大学 <チームフォルダ> "春=<チームフォルダ>/clean/明治国際医療大学_全試合_clean.csv@2026春" "秋=<同じCSV>@2026秋"
```

変換し直すと `config.yaml` が作り直されるので、`pitchers`・`pitchers_short`・`forms` は書き戻す。
滋賀大戦の見出しの期（「24秋・25春」など）は `履歴設定.yaml` の files のラベルから入る。

## 入力データの点検

道具はシーズンのフォルダの `データ点検/`（2026秋は `~/野球/対策資料/2026秋/データ点検/`）にある。
名前対応表で直す前の生データを見る。

- `check_fall.py` … 全試合Excelの「出場選手」シート（大学ごとの名簿）と照らして、名簿にない名前・似た名前を出す。
  あわせて、1人の中で左右がばらつく打者・投手、左右の空欄、ありえないカウント・アウト数・球速、
  投手本人の中央値から20km/h以上外れた球速、球種や結果が空の投球を一覧にする（`点検結果_<期>.csv`）
- `check_hands.py` … 指定した打者の打席を1つずつ、相手投手の左右と並べる。
  スイッチヒッターなら右投手には左打席、左投手には右打席に立つので、合わない打席に印を付ける。
  投手は過去の期と左右が食い違わないかを見る
- `check_hand_games.py` … 全打者について、3期分の多数派と違う打席左右の試合を出す（`打席左右の食い違い.csv`）

わかったこと（2026年9月28日、26秋）
- カウント・アウト数のありえない値は0件。入力ブックのチェックは1試合の中のつじつまは見ているが、
  名簿や過去の試合との食い違いは見ない。左右のミスは「ある試合の入力者が、その打者の全打席をまとめて逆にする」形で起きる
- 球速0は「記録なし」。投手によっては半分以上が0なので、平均を出すときは必ず0を除く
- 名簿（出場選手シート）にも登録漏れや、名前対応表と食い違う表記がある。どちらが正しいかはすばるが決める

## 自チームの分析

対戦前に滋賀大の側を見る分析。置き場は `~/野球/対策資料/<年と季節>/滋賀大学_自チーム分析/`。
`convert_shiga.py 滋賀大学 …` で同じ形に変換してから使う。

- `analyze_self.py` … チームと打者・投手の成績をリーグ全体と比べる
- `lineup.py` … 打順の分析。リーグ全体から24場面（アウト×走者）の得点期待値を作り、
  打者ごとのRE24（得点への貢献）を出す。打者の結果の確率はチーム平均を30打席ぶん混ぜて補正し、
  1イニングずつ確率で追うマルコフ連鎖で9回の期待得点を計算、2人ずつ入れ替えて最良の打順を探す
- `matchup.py` … 相手投手との相性を入れた打順。打者の球種グループ別の成績を、相手投手の決め球の配分（打者の左右別）で重み付けし、
  投手のリーグ平均に対する強さを掛ける（log5の考え方）。直接対戦は数が少ないので参考に表で出す
- `blast_vs_league.py`・`blast_vs_fall.py` … BLAST（練習のスイング）と試合の成績の順位相関と、選手の組み合わせを入れ替える検定。
  すばるの希望で、比べる成績は今季（リアルタイム）だけにした版を使う
- `build_lineup_deck.py`・`build_blast_deck.py` … それぞれA4横の資料（5枚・6枚）を作る

決めたこと
- 期待得点の値そのものは高く出る（弱い相手からの成績、走塁を入れていない）。資料では打順どうしの差だけを見せる
- 打球の強さ（A/B/C）は入力した人の判断が入るので、分析に使わない
- 打順の差は1試合0.1〜0.3点と小さいことを資料に必ず書く。打席の少ない選手の数字は変わりやすいと書く
