# 分析デスク

> 大阪ガスと滋賀大の対策資料のためのMacアプリ。チームフォルダを開き、相手の打者と投手を画面で分析し、
> コメントを書き、今のスクリプトで資料を書き出す。
> コードは別リポジトリの [~/Projects/analysis-desk](../../Projects/analysis-desk/README.md)（まだGitHubには上げていない）。
> 選手データはアプリにもリポジトリにも入れず、チームフォルダを読みに行く。

## 開き方

`~/Applications/分析デスク.app` をダブルクリックする。Spotlightで「分析デスク」と打っても開く。
前回開いていたチームとタブから始まる。

コードを直したら `~/Projects/analysis-desk/scripts/make_app.sh` でアプリを作り直す。

## 何ができるか

| タブ | 中身 |
|---|---|
| 野手 | 公式成績（成績CSV）、1球データから数えた成績、選球（ゾーン内SW率・全体SW率・ゾーン外SW率・空振り率・初球SW率をチーム全体と比べる）、投球図、13分割のゾーン別（スイング率・打率・割合）、打球方向、球種別、カウント別 |
| 投手 | 球速・被打率・三振率・四死球率・ゾーン率、対右・対左、球種ごとの割合と球速と結果、カウント別の配球、決め球、初球、投球図 |
| 資料 | 書き出しボタン（今のスクリプトをそのまま呼ぶ）、進み具合、できた資料の一覧、PDFの表示、PPTXをPowerPointでPDFにする |

野手と投手の画面には、対右・対左、カウント場面（初球・打者有利・中間・追い込み）、球種、期、試合の絞り込みがある。
右側のコメント欄に書くと、チームフォルダの `コメント.yaml`・`投手コメント.yaml` に自動で保存される。
書き換えた欄だけが変わり、ほかの行や説明の行はそのまま残る。最初の保存の前に `.bak_desk` を残す。

## 新しいチームを始める

サイドバーの「＋ 新しいチーム」から、やることを1つずつ案内する画面が開く。左に手順の一覧（済んだものに印）、右に
「やること」と、ファイルを入れる欄がある。作りかけのチームは、チームの見出しの「材料を足す・直す」から続きに戻れる。

| チーム | 手順 |
|---|---|
| 大阪ガス | チーム名 → 打者の1球データ（CSV）→ 公式成績（全体・対右・対左）→ 打者分析のPDF → スタメンと設定 → 投手の1球データ（任意） |
| 滋賀大 | チーム名と季節 → 全試合Excel（前の期・今季）を入れて変換 → スタメンの確認 |

- CSVは、今のスクリプトが読む名前（`全打席結果.csv` など）と形に揃えて置く。成績CSVの見出しの空白も揃える
- 種類の違うCSVや、別のチームの成績を入れたときは、理由を出して止める
- 打者分析のPDFを入れると、ページごとに打者名をMacの文字認識で読み、1球データの打者と突き合わせる。確認の表で直してから
  保存すると、投球図・打球方向（対右・対左）の4枚を切り抜いて4つのフォルダに置く。手で囲む作業と名前リストはいらない
- スタメンは最新の試合の打順から下書きし、守備位置を入れて保存すると `config.yaml` と `team_config.json` ができる
- 滋賀大は、全試合Excelを入れて「変換する」を押すと `convert_shiga.py` が流れ、名前の表記ゆれの候補も出る

日本生命のデータのコピーで、作業用の場所に架空のチームを作り、ファイルの取り込みから書き出し（野手対策・v2・一枚まとめ）まで
通ることを確かめた（PDFの19ページすべての名前が一致）。京都外大の全試合Excelのコピーで、滋賀大の変換も通した（2026-10-09）。

## AIでコメントの下書き

コメント欄の「AIで下書き」で、その選手の集計した数字をClaude（Claude Opus 5.5）に送り、資料の書き方に沿った下書きを返す。

- 送るのは数字だけで、選手名やチーム名は送らない
- 下書きは欄ごとに「使う」を押したときだけ入る。数字は分析の画面と照らし合わせる
- 打者は 全体・対右・対左・警戒、投手は まとめ・球種・左右・対右/対左（割合・カウント・投球図）
- 費用は1人分でおよそ10〜20円の見込み
- キーはサイドバー下の「設定（AI）」で入れる（このMacのキーチェーンに保存）。チャットには貼らない

2026-10-09時点ではキーが入っていないので、実際にClaudeから下書きが返るところは確かめていない。送る中身の組み立てと
返事の読み取りは、架空のデータのテストで確かめた。

## 数え方

判定のルールの正本は `~/Projects/analysis-desk/desk/core/baseball.py`。後輩向けのzipの `baseball.py` から写し、
3点を直した（打席の終わりに失策出塁・野手選択を足す、ボークをスイングに数えない、ゾーンの内と外を分ける13分割）。

- ゾーン内SW率はストライクゾーン（X 40〜160・Y 50〜200）に来た球だけ。全体SW率は全部の球
- 打席は、試合・イニング・打者が同じ球をまとめて区切る。滋賀大のCSVは並び順が時間順とは限らず、結果の行が
  2回入っていることもあるため
- 振り逃げは打席と三振に数える

公式成績CSVと照らし合わせると、7チームのうち2チームは全員一致し、残りは各チーム1人が1打席違う（2026-10-09）。
滋賀大の2件はどちらも振り逃げで、`convert_shiga.py` が振り逃げを打席に数えていないため。

## 分かっている課題

- 大阪ガスのv2データスライドの「Zn内SW」は全球で計算している。アプリは「ゾーン内SW率」と「全体SW率」を並べて出す
- 大阪ガスのコメントは `コメント.yaml` に保存できるが、資料にはまだ自動で入らない
- 滋賀大の `convert_shiga.py` は振り逃げを打席に数えていない
- 大阪ガスの打球方向はCSVに位置がないので、切り抜き画像を出す（滋賀大は打球X・Yから描く）
