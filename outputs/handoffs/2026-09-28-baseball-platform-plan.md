# 野球記録・分析プラットフォーム計画の引き継ぎ

## この作業

既存のExcel VBAによる京滋大学野球の試合入力・分析を、iPad/iPhone/MacアプリとWindows Web版で使えるソフトへ置き換える構想を計画化した。主計画は[野球記録・分析プラットフォーム計画](../../plans/2026-09-28-baseball-scoring-analysis-platform.md)。このファイルはClaudeで続けるときの入口。

## 背景資料

- 元ブックはユーザーのDownloadsにある `分析シート_修正版.xlsm` と `2020年PSS京滋大学野球 (自動保存済み).xlsm`。AI-OSにはコピーしていない。
- 解析時に確認したところ、分析ブックには61個のVBAモジュールがあり、個人/チーム成績、球種・コース、配球、打球方向、得失点、ケース別分析などがある。
- 試合入力ブックには24個のVBAモジュール、入力フォーム、非表示シートがあり、試合記録は191列。
- 現在の滋賀大のExcel分析手順は[滋賀大 対策資料づくり](../../docs/shiga-taisaku.md)。
- 直近の京都外大対策の分析定義・帳票例は[引き継ぎメモ](../../private/shiga-kyogai-2026aki.md)。
- 選手名簿や試合の内部データをAI-OSや公開リポジトリへ入れない。

## いまの設計案

- Apple側はiOS/iPadOS/macOSアプリ、Windows側はブラウザWebアプリ。
- 共通API、データベース、分析計算層を使う。
- 試合記録を新しい意味ベースのデータモデルへ保存し、191列形式はインポート/エクスポートの互換境界として残す。
- iPadは試合中の主入力端末。通信断では端末内へ一時保存し、復帰時に重複なく同期する。初期運用案は1試合1端末入力。
- 推奨技術案はSwiftUI + TypeScript Web/API + PostgreSQLだが、まだ確定ではない。短い試作で共有Web UI案と比較する。
- 全分析を一度に置き換えず、現行Excelと新実装を同じデータで照合し、優先度順に移す。
- 初期案は将来のチーム追加に備えたデータ分離を設けるが、決済や一般公開は含めない。

## 注意点

- これは計画段階で、コード実装や本格的な画面試作はまだ始めていない。
