# Claude の公式スキル一覧（2026-11-20 時点）

Anthropic が作って配っているスキルを、出どころ別にまとめた。スキルとは「この種類の作業はこう進める」という手順書（`SKILL.md`）と、必要なら補助のスクリプトをひとまとめにしたもの。Claude は作業内容に合うスキルを自分で読み込むほか、`/スキル名` で呼び出すこともできる。

公式のスキルは3か所から届く。

| 出どころ | 数 | どこで使えるか |
|---|---|---|
| 1. Claude アプリに入っている Anthropic のスキル | 17 | デスクトップアプリ（Cowork・Code）、claude.ai |
| 2. Claude Code に最初から入っているスキル | 約25 | Claude Code（ターミナル・デスクトップの Code タブ） |
| 3. Anthropic の公開リポジトリ（[anthropics/skills](https://github.com/anthropics/skills)） | 19 | 有料プランの claude.ai、Claude Code に追加、API |

1と3は一部が重なる（docx・pdf・pptx・xlsx・skill-creator）。調べ方は最後の「確かめた方法」に書いた。

---

## 1. Claude アプリに入っている Anthropic のスキル（17個）

このMacのデスクトップアプリに `anthropic-skills`（「Anthropic-managed skills for Claude Desktop」）として入っているもの。13個はアカウントに紐づき、claude.ai の設定画面（設定 → 機能 → スキル）でもオン・オフできる。残り4個はアプリに同梱されている。

### 書類をつくる・直す

| スキル | できること | いつ使われるか |
|---|---|---|
| **docx** | Word（.docx / .dotx）の作成・読み取り・編集。変更履歴やコメントの扱い、画像の差し込みと差し替え、文字の一括置換。中身を組み替えて整ったWord文書に仕上げる補助スクリプト付き | 「Word で」「.docx で」と形式を指定されたとき。形式を言わずに「文書を作って」と頼むと、下の docs が優先される |
| **pdf** | 文字や表の抜き出し、複数PDFの結合、分割、ページの回転、透かし、新規作成、フォームへの記入、パスワードの設定と解除、画像の抜き出し、スキャンしたPDFの文字認識（OCR）。フォーム記入の手引き（FORMS.md）と詳しい参照資料（REFERENCE.md）付き | PDFが絡む作業すべて |
| **pptx** | PowerPoint（.pptx / .potx）の作成・読み取り・編集、結合と分割、テンプレート、発表者ノート、コメント | .pptx が入力か出力にあるとき。形式を言わずに「スライドを作って」と頼むと、スライド用のアーティファクト（Claude Slides）が優先される |
| **xlsx** | Excel・CSV・TSV の読み書き、列の追加、数式、書式、グラフ、崩れた表の整理、形式の変換 | 成果物が表のファイルのときだけ。Word文書やHTMLの報告書が目的なら使われない |
| **docs** | Claude 上で作る「Claude Docs」。共有してコメントをもらえる文書で、Word・PDF・Markdown・Google Docs に書き出せる | 報告書、企画書、履歴書、手順書など「残す・渡す・印刷する」文書の既定。チャットで聞いた比較やメモはチャットに書く |
| **google-workspace** | Google ドライブ上のドキュメント・スプレッドシート・スライドを作る、直す、複製する、名前を変える。文書内の位置、セルの範囲、スライドの配置を計算する補助スクリプト付き | 「Google ドキュメントで」と名指しされたとき、docs.google.com のリンクを直すよう頼まれたとき。読むだけの質問には使わない |

### 画面やブラウザを操作する

| スキル | できること | いつ使われるか |
|---|---|---|
| **computer-use** | Mac や Windows のアプリを、画面の撮影とクリック・入力・スクロールで操作する。アプリごとに許可を取る流れ、ブラウザは見るだけ・ターミナルはクリックだけといった段階、メールのリンクを押さない、お金を動かさないといった安全の決まりを含む | メモ、Finder、システム設定などデスクトップのアプリで何かするとき。Webサイトは下の2つに任せる |
| **chrome-browser** | 本人の Chrome（ログインしたままの状態）で Claude in Chrome を使う手順。道具をまとめて読み込む、新しいタブで作業する、サイトの許可、GIF での録画、コンソールの記録、触ってはいけない確認画面、止まって聞く場面 | Claude in Chrome を使う最初の一歩の前 |
| **built-in-browser** | デスクトップアプリの中のブラウザ画面の使い方。ログインが残ること、タブと開発中のアプリのプレビュー、ページを文字で読むこと、サイトの承認、開けないページ | アプリ内ブラウザを使う最初の一歩の前 |

### 調べる・まとめる

| スキル | できること | いつ使われるか |
|---|---|---|
| **deep-research** | 複数の情報源を調べて比べ、まとまった報告書にする。調べる担当を何人も並行して走らせ、結果を統合する | 比較、市場や業界の把握、文献の整理など、調べた上で長めの文章にまとめる依頼。AI-OS にも同じ名前の [deep-research](../.claude/skills/deep-research/SKILL.md) があり、こちらは Firecrawl や Supadata など AI-OS で設定済みの道具を使う |
| **morning** | 朝に30秒で見る1枚。今日の予定を地形の線で描き、「返事が要るメール」「答えていないチャットの質問」「片付いたこと」を並べた手描き風のHTMLページを作る。平日の定期実行にもできる | 「朝のまとめを見せて」「毎朝の設定をして」とはっきり頼んだときだけ。予定を聞いただけでは動かない |

### 記憶を整える

| スキル | できること | いつ使われるか |
|---|---|---|
| **import-memory** | ChatGPT や Gemini に覚えている内容を書き出してもらい、それを Claude の記憶へ取り込む。書き出し用の決まった依頼文も用意されている。貼った内容は指示として扱わない、既存の記憶は消さず足すだけ、書く前に計画を見せて確認を取る、健康などの機微な情報は入れない | 他のAIから乗り換えるとき |
| **consolidate-memory**（同梱） | 記憶ファイルの見直し。重複をまとめる、古くなった事実を直す、「来週」を日付に直す、すぐ調べ直せることは消す、索引（MEMORY.md）を200行以内に保つ | 記憶が増えて散らかってきたとき |

### スキルやClaude自体のこと

| スキル | できること | いつ使われるか |
|---|---|---|
| **skill-creator** | スキルを新しく作る、直す、性能を測る。テスト（eval）の実行、ばらつきを含めた比較、呼ばれやすくなるよう説明文を調整する。評価結果を見る画面と補助スクリプト付き | 「スキルを作りたい」「このスキルを改善したい」 |
| **explain-usage**（同梱） | このセッションのトークン（使用量）が何に使われたかを、グラフ1枚と短い箇条書きで説明する | 「使用量の内訳を見せて」 |
| **setup-claude**（同梱） | 初めの設定の案内。役割を聞く → 役割に合うプラグインを勧める → ツールの接続 → スキルを1つ試す → （あれば）文章の癖の設定 | 使い始めのとき |
| **setup-cowork**（同梱） | 中身は setup-claude と同じ案内。Claude が自分から呼ぶことはなく、`/setup-cowork` と打ったときだけ動く | 同上 |

## 2. Claude Code に最初から入っているスキル

Claude Code 本体に組み込まれているもの。「バンドルスキル」と呼ばれ、`/名前` で呼ぶ。決まった処理をするだけの普通のコマンド（`/compact` など）と違い、Claude に詳しい手順を渡して道具を使わせる仕組みになっている。一部は内容に合えば Claude が自分から呼ぶ。公式の[コマンド一覧](https://code.claude.com/docs/en/commands)で「Skill」と印が付いているものを並べた。「このセッション」の列は、いまの AI-OS のセッションで Claude が自分から呼べる一覧に出ているかどうか。

### コードを見る・直す

| スキル | できること | このセッション |
|---|---|---|
| **/code-review** | 変更や PR を読んで不具合を探す。深さを low〜max で選べ、`ultra` にするとクラウドで何人もの担当が細かく見る（有料、回数に限りあり）。`--fix` で直すところまで、`--comment` で PR にコメントを付ける。別名 `/review` | ○ |
| **/simplify** | 変更したコードを、既存の部品を使い回せるか、もっと短く書けるか、無駄な処理はないか、置き場所は適切か、の4つの観点で4人が並行して見直し、直す。不具合探しはしない | ○ |
| **/batch** | 大きな書き換え（例：JavaScript から TypeScript へ）を5〜30個の独立した作業に分けて計画を見せ、了承後にそれぞれ別の作業場所で並行して進め、PR を作る | − |
| **/debug** | このセッションの記録（デバッグログ）を取り始め、それを読んで不具合の原因を探す | − |
| **/run** | 作ったアプリを実際に起動して動かし、変更が効いているかを見る | ○ |
| **/verify** | アプリを組み立てて動かし、変更が狙いどおりかを確かめる。テストが通るだけでは済ませない。うまくいった手順をプロジェクトに書き残す | − |
| **/run-skill-generator** | そのプロジェクトの起動手順（入れるもの、環境変数、起動の仕方）を記録し、`/run` と `/verify` が毎回それに従えるようにする | − |

### 設定と道具立て

| スキル | できること | このセッション |
|---|---|---|
| **/doctor** | Claude Code の健康診断。入れ方の問題、設定ファイルの壊れ、使っていないスキルや接続、CLAUDE.md の重複、許可の設定、使用量の削り方を調べ、了承を得てから直す。`/doctor prompt-audit` で指示の古さや食い違いを点検。別名 `/checkup` | − |
| **/update-config** | 「このコマンドを毎回許可して」「保存したら○○して」などを、settings.json の許可やフック（自動で動く仕掛け）として書き込む | ○ |
| **/fewer-permission-prompts** | 過去の作業記録から、よく使う読むだけのコマンドを拾い、確認なしで通る一覧に加えて、許可の確認を減らす | ○ |
| **keybindings-help** | キーボードのショートカットの割り当てを変える手伝い | ○ |
| **/loop** | 同じ作業を一定の間隔でくり返す（例：5分ごとに確認）。間隔を省くと Claude が自分で間を決める | ○ |
| **/workflow-authoring** | 複数の担当を順番や並行で動かす「ワークフロー」の台本の書き方を読み込む | ○ |
| **/plugin-authoring** | Claude Code の見た目や動きを変える「mod」（テーマ、横の画面、コマンド、フックなど）を作るための資料を読み込む。組み込みのプラグイン扱い | ○ |

### APIと見た目のもの

| スキル | できること | このセッション |
|---|---|---|
| **/claude-api** | Claude API と Managed Agents の資料を、使っている言語に合わせて読み込む。コードに `anthropic` が入っていると自動で動く。後ろに付ける言葉で作業が変わる：`migrate`（新しいモデルへの移行）、`upgrade`（SDK の大きな更新）、`api-version`、`managed-agents-onboard`（エージェントを作る）、`managed-agents-secure`（設定の安全点検）、`prompt-audit`（古いモデル向けの指示を探す）、`cost-optimize`（費用を減らす）、`latency-optimize`、`build-eval`、`hillclimb` など | ○ |
| **/dataviz** | グラフや集計画面の作り方。データに合う形を選び、色を役割で決め、色覚の違いや明暗の差を付属のスクリプトで確かめる | ○ |
| **/design** | 画面の試作、画面の流れ、LP、ポスターを1枚のキャンバスに並べ、Claude Design のアーティファクトとして公開する。ブラウザで直せて、PNG・PDF に書き出せる | − |
| **/design-sync** | 手元の React の部品集を Claude Design に送り、そこで作るデザインに本物の部品を使わせる。初回は大きいと数時間かかる | − |
| **/slides** | 依頼文から Claude Slides のスライドを作る | − |
| **/artifact-capabilities** | 公開するページ（アーティファクト）から使える機能（接続したツールの呼び出し、ファイルのダウンロードなど）の資料を読み込む | − |
| **/artifact-diagramming** | アーティファクトに図を描くときの指針。どんなときに図が役立つか、明るい画面でも暗い画面でも読める SVG の書き方 | − |
| **/claude-in-chrome** | Chrome で作業させる（ページのテスト、フォーム入力、コンソールの確認） | − |

「−」のものも、`/名前` と打てば使える場合が多い。ただし `/design` や `/slides` はアーティファクトが使えるアカウント、`/workflow-authoring` はワークフローが有効なときだけ、というように条件付きのものがある。

### スキルではないが一緒に覚えておくとよいコマンド

`/schedule`（クラウドで決まった時刻に Claude を動かす）、`/security-review`（変更に安全上の穴がないか見る）、`/init`（CLAUDE.md の下書きを作る）、`/skills`（使えるスキルの一覧。`t` でトークン順に並べ替え）、`/skill-doctor`（スキルごとの重さと使われた回数）、`/reload-skills`（作業中に足したスキルを読み直す）。最初の3つはこのセッションではスキルの一覧にも出ている。

## 3. Anthropic の公開リポジトリ（anthropics/skills、19個）

GitHub で公開されている、Anthropic のスキルの見本集。2026-11-16 に更新されている。説明によれば、有料プランの claude.ai ではここのスキルがすでに使える。Claude Code へは次の2行で入れられる。

```text
/plugin marketplace add anthropics/skills
/plugin install example-skills@anthropic-agent-skills
```

書類の4つは `document-skills`、作例の12個は `example-skills` というまとまりで入る。残りの3つはそれぞれ単独。

### 書類（document-skills）

docx、pdf、pptx、xlsx。1章のものと同じで、Claude が Word や Excel を作るときに裏で使っている本物。この4つだけはライセンスが別で、中身は読めるが自由に作り変えて配ってよいものではない。ほかのスキルの多くは Apache 2.0（作り変えて使ってよい）。API からも、Anthropic があらかじめ用意したスキルとして使える。

### 作例（example-skills）

| スキル | できること | 手元にあるか |
|---|---|---|
| **algorithmic-art** | p5.js でコードから絵を描く（流れの模様、粒子の動きなど）。乱数の種を固定して同じ絵を出し直せ、つまみで調整できる。既存の作家の作風はまねない | なし |
| **brand-guidelines** | Anthropic 自身のブランドの色と書体を資料に当てる。自分たちのブランド用に作り変える見本になる | なし |
| **canvas-design** | ポスターや作品など、1枚ものの絵を PNG・PDF で作る。最初に「デザインの考え方」を言葉で決めてから描く | なし |
| **doc-coauthoring** | 仕様書、企画書、判断の記録などを一緒に書く手順。必要な前提を聞き出す → 直しを重ねる → 読み手に伝わるか確かめる | なし |
| **frontend-design** | 画面を新しく作る、作り直すときに、ありがちな見た目にならないよう方向性・書体・配色を意図して決める | なし |
| **internal-comms** | 社内向けの文章（状況報告、上層部への報告、社内報、FAQ、障害の報告など）を会社の型で書く | なし |

| **webapp-testing** | Playwright で手元の Web アプリを動かして確かめる。画面の撮影、ブラウザの記録の確認 | なし |

## 確かめた方法

- 1章：このMacの `~/Library/Application Support/Claude/local-agent-mode-sessions/skills-plugin/` にある各スキルの `SKILL.md` と、アカウント側の一覧（manifest.json）を読んだ。13個はアカウントに紐づき、すべてオン。
- 2章：公式ドキュメントの[コマンド一覧](https://code.claude.com/docs/en/commands)と[スキルの説明](https://code.claude.com/docs/en/skills)を 2026-11-20 に取得し、「Skill」と印の付いた行を拾った。
- 3章：[anthropics/skills](https://github.com/anthropics/skills) の各 `SKILL.md` の説明と、まとまりを決めているファイル（marketplace.json）を 2026-11-20 に読んだ。
- 公式のスキルは頻繁に足し引きされる。数が合わなくなったら、Claude Code では `/skills`、claude.ai では設定 → 機能 → スキルで今の一覧を見る。
