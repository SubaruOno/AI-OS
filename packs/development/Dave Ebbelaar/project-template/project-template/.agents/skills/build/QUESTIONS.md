# Design questions

Pick at most three per slice, from the section that matches. Ask one at a time.

Every question names two options and says what each one means for the business. When there is no genuine choice, pick the sensible thing and say so. A fake question spends attention you need for the real ones.

## Forms

**How much do you want to require?**
Everything up front, so records are always complete but people abandon the form. Or the minimum, so it is quick to file and some records need chasing later.

**What happens after they submit?**
Straight back to the list, which is faster when filing several. Or onto the record just created, which is better when the next thing is usually to add detail.

**Can it be changed afterwards?**
Yes, which is forgiving and means you cannot fully trust an old record. No, which keeps a clean history and means mistakes need a new entry.

## Lists

**What do you want to see without clicking?**
Name three or four things. Everything else lives on the detail screen. A list that shows everything is a list nobody reads.

**What order?**
Newest first, which suits things you act on. Or by urgency, which suits things you work through.

**What about the finished ones?**
Hide them, so the screen is what needs attention. Or show them greyed out, so the history stays visible. Hidden is usually right, and one filter brings them back.

## Reports and numbers

**One number or the working?**
The number alone, which is read at a glance. Or the number with the rows behind it, which can be checked when it looks wrong.

**How current?**
Worked out every time it is opened, which is always right and slower. Or worked out overnight, which is instant and up to a day old.

## Uploads

**What can they upload?**
Name the file types. Anything else gets refused with a message. A tight list is a guardrail.

**What happens if it fails?**
Say so immediately and let them retry. Or accept it, work on it in the background, and tell them when it is ready. The second is right when the work takes more than a few seconds.

## Notifications

**Immediately or in a batch?**
Each one as it happens, which is urgent and becomes noise. Or a daily summary, which is calm and can be a day late.

**Who gets it?**
One person, which is clear about who acts. Or everyone, which is safer and means nobody feels responsible. Name the person if you can.

## Anything with AI

**What happens when it is unsure?**
Show its best guess flagged for checking, which is fast and needs someone to look. Or set it aside for a person, which is slower and safer.

Ask this every time. AI output is something a person checks, not the final word, and where that check happens is a real business decision.

**Who sees it before the customer does?**
Nobody, which is fast. Or you, which is slower and stops the embarrassing one going out. For anything that leaves the company, the second is usually right the first few months.

## Money

**What currency, and how is it stored?**
Always store amounts as whole cents, never as decimals. Decimal arithmetic on money produces a penny that goes missing and cannot be traced. Ask which currency, tell them how it is stored, and move on.

**What about tax?**
Store the amount before tax and work the rest out, or store the total. This depends on their accounting, so ask rather than assume.

## When they cannot answer

Give a recommendation and say what it commits them to.

> I'd hide finished ones by default, with a filter to bring them back. That keeps your screen to what needs doing. If it turns out you look at old ones often, we flip it, and that is a five-minute change.

Record the recommendation in `project/DECISIONS.md` the same way as a choice. Six weeks later, "we picked this without a strong opinion" is useful information.
