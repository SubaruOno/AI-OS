# Level 3: website plus a separate engine

For work that takes more than a moment: reading PDFs, running AI over long documents, chewing through big spreadsheets, running on a schedule.

Two pieces. A Python backend does the heavy work. A React website talks to it. They deploy separately.

Read [`_dependency-policy.md`](_dependency-policy.md) first.

## The security posture

The browser holds no Supabase key at all. Its only setting is the address of your own backend. The backend reaches the database directly with a password.

Turn the automatic web API off entirely: Supabase dashboard, Settings, Data API, disable. The generated endpoints then stop answering regardless of keys or permissions. It is the strongest guardrail Supabase offers and it costs nothing.

Row security stays on with no rules, same as level 1.

## 1. Create the Supabase project

Start this first and do the rest while it provisions.

1. [supabase.com/dashboard](https://supabase.com/dashboard), new project, save the database password.
2. Settings, then Data API: disable it.
3. Connect, then **Session pooler**: copy that connection string.

Use the session pooler on port 5432, not the transaction pooler on 6543. SQLAlchemy holds connections open and uses prepared statements, which transaction mode breaks.

Do not use the direct `db.<ref>.supabase.co` address. It answers on IPv6 only, Railway sends IPv4, and the failure looks like a wrong password.

## 2. Backend

```bash
mkdir -p backend/app && cd backend
uv init --bare --python 3.12
```

Write the policy into `pyproject.toml` **before adding anything**:

```toml
[tool.uv]
add-bounds = "exact"
exclude-newer = "7 days"
package = false

[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

Then add by bare name:

```bash
uv add fastapi "uvicorn[standard]" pydantic pydantic-settings sqlalchemy "psycopg[binary]"
uv add --dev ruff
```

Add `uv add "pyjwt[crypto]"` only when the website uses Supabase sign-in. Use PyJWT rather than python-jose, which is unmaintained.

### Layout

```
backend/
  app/
    main.py           builds the app
    config.py         the only file reading the environment
    database.py       engine and session
    <domain>/         one folder per part of the business
      routes.py       HTTP only
      service.py      the actual decisions
      repository.py   the only place touching the database
      models.py       table definitions
      schemas.py      what goes in and out over HTTP
      validation.py   business rules, no I/O
  pyproject.toml
  uv.lock
  .python-version     contains: 3.12
  .env / .env.example
  railway.json
```

One folder per part of the business, each holding its whole stack. Routes translate HTTP and nothing else. Services decide. Repositories are the only code that touches the database. Validation is pure rules, so you can read it and tell whether it is right.

Third-party SDK types stop at their own adapter file. When the vendor changes their response shape, one file changes.

### `app/config.py`

The only file in the backend that reads the environment. No `os.getenv` and no `load_dotenv` anywhere else.

```python
from functools import lru_cache
from pathlib import Path

from pydantic_settings import BaseSettings, SettingsConfigDict

BACKEND_ROOT = Path(__file__).resolve().parents[1]


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=BACKEND_ROOT / ".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )

    database_url: str
    allowed_origin: str = "http://localhost:5173"


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

Fields without a default are required, so a missing setting stops startup with the name of what is missing.

### `app/main.py`

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.config import get_settings


def create_app() -> FastAPI:
    settings = get_settings()
    app = FastAPI(title="Backend", version="0.1.0")

    app.add_middleware(
        CORSMiddleware,
        allow_origins=[settings.allowed_origin],
        allow_credentials=True,
        allow_methods=["*"],
        allow_headers=["*"],
    )

    @app.get("/health")
    def health() -> dict[str, str]:
        return {"status": "ok"}

    return app


app = create_app()
```

`allow_origins` names one exact address. Browsers refuse `["*"]` together with `allow_credentials=True`, so widening it to fix a CORS error produces a different CORS error.

### `backend/.env.example`

```bash
# Supabase, then Connect, then Session pooler. Port 5432.
DATABASE_URL=postgresql+psycopg://postgres.your-project-ref:YOUR-DB-PASSWORD@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
ALLOWED_ORIGIN=http://localhost:5173
```

## 3. Frontend

```bash
pnpm create vite@latest frontend -- --template react-ts
cd frontend
printf 'savePrefix: ""\nminimumReleaseAge: 10080\nminimumReleaseAgeStrict: true\n' > pnpm-workspace.yaml
node -e 'const f="package.json",p=require("./"+f);delete p.dependencies;delete p.devDependencies;p.scripts.typecheck="tsc -b --noEmit";require("fs").writeFileSync(f,JSON.stringify(p,null,2)+"\n")'
pnpm add react react-dom
pnpm add -D vite @vitejs/plugin-react typescript @types/react @types/react-dom @types/node \
            tailwindcss @tailwindcss/vite eslint @eslint/js typescript-eslint globals \
            eslint-plugin-react-hooks eslint-plugin-react-refresh
```

Two runtime packages, react and react-dom. No router, no state library, no HTTP library. `fetch` is built into the browser and `useState` handles state until it genuinely does not.

### Layout

```
frontend/
  src/
    main.tsx
    App.tsx
    index.css           starts with: @import "tailwindcss";
    lib/
      env.ts            the only file reading import.meta.env
      api.ts            the only file calling the backend
      types.ts
    components/
  vite.config.ts
  .env / .env.example
```

`src/lib/env.ts`:

```ts
const configured = import.meta.env.VITE_API_BASE_URL

if (!configured) {
  throw new Error('VITE_API_BASE_URL is required')
}

export const apiBaseUrl = configured === '/' ? '' : configured.replace(/\/$/, '')
```

`src/lib/api.ts` holds one private `request<T>` helper and one small exported function per endpoint. Components call those functions and never call `fetch` directly, so when the backend changes, one file changes.

`vite.config.ts`:

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: { port: 5173, strictPort: true },
})
```

## 4. Lock the database down

Create `supabase/migrations/0000_lockdown.sql` from [`../security/migrations.md`](../security/migrations.md) and push it. Tables use the template from that file **without** the level 2 grant and policy block.

## 5. Run both

```bash
cd backend  && uv sync --locked
cd frontend && pnpm install --frozen-lockfile
```

Then create `scripts/dev.sh` to start them together:

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."

( cd backend  && uv run --locked --no-sync uvicorn app.main:app --reload --port 8000 ) &
( cd frontend && pnpm dev ) &

trap 'kill 0' EXIT INT TERM
wait
```

`--no-sync` means the startup script never installs or updates anything.

## 6. Check it

```bash
cd backend  && uv run --locked --no-sync ruff check . && uv run --locked --no-sync ruff format --check .
cd frontend && pnpm lint && pnpm typecheck && pnpm build
./scripts/preflight.sh
```

## Adding sign-in

When people need their own accounts, the website gets `@supabase/supabase-js` and the publishable key, uses it **for sign-in only**, and sends the resulting token to your backend as `Authorization: Bearer <token>`.

The backend verifies it with PyJWT against `https://<ref>.supabase.co/auth/v1/.well-known/jwks.json`, with `issuer=https://<ref>.supabase.co/auth/v1`, `audience=authenticated`, `algorithms=["RS256","ES256"]`.

The Data API stays off. Sign-in runs on a different endpoint and keeps working.
