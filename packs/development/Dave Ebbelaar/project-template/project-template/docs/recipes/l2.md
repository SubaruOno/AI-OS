# Level 2: everyone signs in, everyone sees their own

For an app where different people should see different records. Each person signs in with their own email, and the database enforces who sees what.

Read [`_shared-nextjs.md`](_shared-nextjs.md) and [`_dependency-policy.md`](_dependency-policy.md) first.

## The security posture

The browser holds the publishable key and talks to Supabase directly. That key can only do what your row security rules allow, so **the rules are the wall**. This is the one level where getting the rules right is what keeps people out of each other's data.

Exactly two settings are public: the project URL and the publishable key. The secret key does not exist in this project unless a specific job needs it and you wrote down why.

## 1. Create the Supabase project

Start this first, it takes about two minutes, and do the rest while it runs.

1. [supabase.com/dashboard](https://supabase.com/dashboard), new project, region near you, save the database password.
2. Authentication, then Providers: keep Email on. Turn off "Confirm email" for now if you want to test quickly, and turn it back on before real users arrive.
3. Project Settings, then API Keys: copy the project URL and the **publishable** key (`sb_publishable_…`).

Leave the secret key where it is. You do not need it.

## 2. Scaffold

Follow the scaffolding section of [`_shared-nextjs.md`](_shared-nextjs.md), taking the **level 2** package line.

## 3. Layout

```
app/
  layout.tsx
  page.tsx
  actions.ts
  auth/
    login/page.tsx
    callback/route.ts
lib/
  env.ts                the only file reading the public settings
  supabase/
    client.ts           for browser components
    server.ts           for pages, actions, route handlers
    proxy.ts            keeps the session fresh
proxy.ts
supabase/
  config.toml
  migrations/
.env.local
.env.example
.stack-level            contains: l2
```

Three Supabase clients, because three places need one and they get their session from different places. Using the wrong one is the most common level 2 mistake: a browser client in a page loses the session, a server client in a browser component fails to build.

## 4. The files that matter

`.env.example`, the whole file:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_replace_me
```

`lib/env.ts`:

```ts
function required(name: string, value: string | undefined): string {
  if (!value) throw new Error(`Missing required setting: ${name}`);
  return value;
}

// Each process.env name is written out in full. Next.js substitutes the
// literal text at build time, so a computed name produces nothing.
export const publicEnv = {
  supabaseUrl: required("NEXT_PUBLIC_SUPABASE_URL", process.env.NEXT_PUBLIC_SUPABASE_URL),
  supabasePublishableKey: required(
    "NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY",
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY,
  ),
} as const;
```

`lib/supabase/client.ts`:

```ts
import { createBrowserClient } from "@supabase/ssr";
import { publicEnv } from "@/lib/env";

export function createClient() {
  return createBrowserClient(publicEnv.supabaseUrl, publicEnv.supabasePublishableKey);
}
```

`lib/supabase/server.ts`:

```ts
import { createServerClient } from "@supabase/ssr";
import { cookies } from "next/headers";
import { publicEnv } from "@/lib/env";

// Built fresh per request. A module-level singleton would let one visitor's
// session leak into another visitor's request.
export async function createClient() {
  const cookieStore = await cookies();

  return createServerClient(publicEnv.supabaseUrl, publicEnv.supabasePublishableKey, {
    cookies: {
      getAll() {
        return cookieStore.getAll();
      },
      setAll(cookiesToSet, _headers) {
        try {
          cookiesToSet.forEach(({ name, value, options }) =>
            cookieStore.set(name, value, options),
          );
        } catch {
          // Called from a page rather than an action. proxy.ts refreshes the session.
        }
      },
    },
  });
}
```

`lib/supabase/proxy.ts`:

```ts
import { createServerClient } from "@supabase/ssr";
import { NextResponse, type NextRequest } from "next/server";
import { publicEnv } from "@/lib/env";

export async function updateSession(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request });

  const supabase = createServerClient(publicEnv.supabaseUrl, publicEnv.supabasePublishableKey, {
    cookies: {
      getAll() {
        return request.cookies.getAll();
      },
      setAll(cookiesToSet, headers) {
        cookiesToSet.forEach(({ name, value }) => request.cookies.set(name, value));
        supabaseResponse = NextResponse.next({ request });
        cookiesToSet.forEach(({ name, value, options }) =>
          supabaseResponse.cookies.set(name, value, options),
        );
        Object.entries(headers).forEach(([key, value]) =>
          supabaseResponse.headers.set(key, value),
        );
      },
    },
  });

  // Put no code between createServerClient and getUser(). Anything in between
  // makes people get signed out at random, and it is very hard to trace.
  const {
    data: { user },
  } = await supabase.auth.getUser();

  if (!user && !request.nextUrl.pathname.startsWith("/auth")) {
    const url = request.nextUrl.clone();
    url.pathname = "/auth/login";
    return NextResponse.redirect(url);
  }

  // Return this exact object. Building a fresh response drops the cookies and
  // ends the visitor's session.
  return supabaseResponse;
}
```

The second argument to `setAll` is `headers`, and copying those headers onto the response is what stops a shared cache from serving one person's session to another. Most examples online predate it and leave it out.

`proxy.ts`:

```ts
import type { NextRequest } from "next/server";
import { updateSession } from "@/lib/supabase/proxy";

export async function proxy(request: NextRequest) {
  return await updateSession(request);
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)"],
};
```

`app/auth/callback/route.ts`:

```ts
import { NextResponse, type NextRequest } from "next/server";
import { createClient } from "@/lib/supabase/server";

export async function GET(request: NextRequest) {
  const { searchParams, origin } = new URL(request.url);
  const code = searchParams.get("code");
  const next = searchParams.get("next") ?? "/";

  if (code) {
    const supabase = await createClient();
    const { error } = await supabase.auth.exchangeCodeForSession(code);
    if (!error) return NextResponse.redirect(`${origin}${next}`);
  }

  return NextResponse.redirect(`${origin}/auth/login?error=1`);
}
```

## 5. Every server action checks first

The proxy protects screens. It does not protect a server action, because an action is a URL anyone can call.

```ts
"use server";

import { createClient } from "@/lib/supabase/server";

export async function createOrder(formData: FormData) {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) throw new Error("Not signed in");

  // ... the actual work
}
```

First line, every action. Row security is the second wall behind this one, and it is what saves you when this check is forgotten.

## 6. Lock the database down, then build tables

Create `supabase/migrations/0000_lockdown.sql` from [`../security/migrations.md`](../security/migrations.md), then:

```bash
pnpm dlx supabase@latest login
pnpm dlx supabase@latest init
pnpm dlx supabase@latest link --project-ref YOUR_PROJECT_REF
pnpm dlx supabase@latest db push
```

Every table then uses the full template from that file, **including** the grant and the four policies. Read the "Rules that are easy to get wrong" section there before writing your first one. Those five mistakes each produce an app that appears to work and leaks.

## 7. Run it

```bash
pnpm install --frozen-lockfile
pnpm dev
```

## 8. Prove the rules work

This is the check that matters.

1. Sign up as `you+one@yourdomain.com`. Create a record.
2. Sign out. Sign up as `you+two@yourdomain.com`.
3. Look for the first account's record.

Seeing nothing is the pass. Seeing the record means a policy is missing or wrong, and the app is not ready for anyone.

Then:

```bash
pnpm lint
pnpm typecheck
pnpm build
./scripts/preflight.sh
```
