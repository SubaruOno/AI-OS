# Level 1: one website, one shared password

For a tool a handful of trusted people use, where everyone seeing everything is fine.

Read [`_shared-nextjs.md`](_shared-nextjs.md) and [`_dependency-policy.md`](_dependency-policy.md) first.

## The security posture

The browser never talks to Supabase. Your server does, holding the secret key, and sends finished screens to the browser. There are zero public settings in the entire project.

The database has row security on with no rules and no permissions handed out. Nobody can write a bad rule, because the correct number of rules is zero.

A shared password sits in front of every page. Vercel's free plan cannot put a login wall in front of a live site, so without this gate an internal tool is a public website.

## 1. Create the Supabase project

Start this first, it takes about two minutes to provision, and do the rest while it runs.

1. Open [supabase.com/dashboard](https://supabase.com/dashboard) and create a new project.
2. Pick a region near you. Save the database password somewhere safe.
3. While it provisions, keep going.

Once it is ready: Project Settings, then API Keys. You need the project URL and the **secret** key (`sb_secret_…`).

## 4. The four files that matter

`.env.example`:

```bash
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SECRET_KEY=sb_secret_replace_me
APP_PASSWORD=replace-with-a-long-passphrase
APP_SESSION_SECRET=replace-with-64-random-hex-chars
```

Generate the last one with `openssl rand -hex 32`.

`lib/env.server.ts`:

```ts
function required(name: string, value: string | undefined): string {
  if (!value) throw new Error(`Missing required setting: ${name}`);
  return value;
}

export const serverEnv = {
  supabaseUrl: required("SUPABASE_URL", process.env.SUPABASE_URL),
  supabaseSecretKey: required("SUPABASE_SECRET_KEY", process.env.SUPABASE_SECRET_KEY),
  appPassword: required("APP_PASSWORD", process.env.APP_PASSWORD),
  appSessionSecret: required("APP_SESSION_SECRET", process.env.APP_SESSION_SECRET),
} as const;
```

A missing setting stops startup and names itself.

`lib/supabase/admin.ts`:

```ts
import "server-only";
import { createClient } from "@supabase/supabase-js";
import { serverEnv } from "@/lib/env.server";

/** Holds the key that ignores row security. Server code only.
 *  The build fails if a browser component imports this file. */
export function createAdminClient() {
  return createClient(serverEnv.supabaseUrl, serverEnv.supabaseSecretKey, {
    auth: { persistSession: false, autoRefreshToken: false },
  });
}
```

`lib/session.ts`:

```ts
import { createHmac, timingSafeEqual } from "node:crypto";
import { serverEnv } from "@/lib/env.server";

export const SESSION_COOKIE = "app_session";
const MAX_AGE_SECONDS = 60 * 60 * 24 * 30;

function sign(payload: string): string {
  return createHmac("sha256", serverEnv.appSessionSecret).update(payload).digest("base64url");
}

export function issueSession(): { value: string; maxAge: number } {
  const expiresAt = String(Date.now() + MAX_AGE_SECONDS * 1000);
  return { value: `${expiresAt}.${sign(expiresAt)}`, maxAge: MAX_AGE_SECONDS };
}

export function isValidSession(raw: string | undefined): boolean {
  if (!raw) return false;
  const [expiresAt, signature] = raw.split(".");
  if (!expiresAt || !signature) return false;
  const expected = Buffer.from(sign(expiresAt));
  const actual = Buffer.from(signature);
  if (expected.length !== actual.length) return false;
  if (!timingSafeEqual(expected, actual)) return false;
  return Number(expiresAt) > Date.now();
}

export function passwordMatches(candidate: string): boolean {
  const expected = Buffer.from(serverEnv.appPassword);
  const actual = Buffer.from(candidate);
  if (expected.length !== actual.length) return false;
  return timingSafeEqual(expected, actual);
}
```

`timingSafeEqual` compares in constant time, so the comparison itself does not leak how much of the password was right.

`proxy.ts`:

```ts
import { NextResponse, type NextRequest } from "next/server";
import { SESSION_COOKIE, isValidSession } from "@/lib/session";

export function proxy(request: NextRequest) {
  if (request.nextUrl.pathname.startsWith("/login")) return NextResponse.next();
  if (isValidSession(request.cookies.get(SESSION_COOKIE)?.value)) return NextResponse.next();
  const url = request.nextUrl.clone();
  url.pathname = "/login";
  return NextResponse.redirect(url);
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)"],
};
```

`lib/env.server.ts` and `lib/session.ts` carry no `server-only` marker, because `proxy.ts` imports them and that marker does not resolve in the proxy bundle. `lib/supabase/admin.ts` is never imported by the proxy, so it keeps the marker and the build-time guarantee. `scripts/check-secrets.sh` covers the other two. This asymmetry is deliberate.

## 5. Lock the database down

Create `supabase/migrations/0000_lockdown.sql` with the contents from [`../security/migrations.md`](../security/migrations.md), then:

```bash
pnpm dlx supabase@latest login
pnpm dlx supabase@latest init
pnpm dlx supabase@latest link --project-ref YOUR_PROJECT_REF
pnpm dlx supabase@latest db push
```

Every table after this uses the template from that same file, **without** the level 2 grant and policy block.

## 6. Run it

```bash
pnpm install --frozen-lockfile
pnpm dev
```

Open `http://localhost:3000`. The password screen should appear.

## 7. Check it

```bash
pnpm lint
pnpm typecheck
pnpm build
./scripts/preflight.sh
```

At level 1, `check-secrets.sh` runs with an empty allowlist. Any `NEXT_PUBLIC_` name at all is a finding.
