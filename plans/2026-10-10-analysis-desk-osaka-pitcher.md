# Plan: 分析デスクで大阪ガスの投手対策を作れるようにする

**Created:** 2026-10-10
**Status:** Implemented
**Request:** 大阪ガスの投手対策をアプリで選べるようにする（2026-10-10、すばるが「1〜5を全部作る」を選んだ）。
**Purpose:** 東海理化の回（2026-10-10）で決まった投手対策の作り方を、アプリの案内と書き出しでそのまま行えるようにする。

---

## Overview

### What This Plan Accomplishes

[分析デスク](../docs/analysis-desk.md)の「新しいチーム」で、大阪ガスは野手対策・投手対策・両方を選べるようにする。投手対策は、BASSの元データ → データを直す → 相手の攻撃側のデータ → 試合一覧と作戦 → 資料、の順に案内する。書き出しは草案から作るボタンと、直したコメントのまま作り直すボタンに分ける。投手のコメント欄は、資料が読むコメントのMDに読み書きする。

### Why This Matters

今のアプリは大阪ガスの投手対策を昨日までの手順で書き出し、手で直したコメントを草案で上書きしてしまう。アプリで書いたコメントも資料に入らない。

## Current State

### Relevant Existing Structure

- 投手対策の作り方は `~/大阪ガス/CLAUDE.md` の「投手対策の作り方」（2026-10-10更新）。入口は [対策資料づくり](../private/osakagas-taisaku.md)
- スクリプト（`~/大阪ガス/分析ツール/pitcher_analysis/`）
  - `clean_pitch_csv.py <BASS元.csv> <修正リスト.json> <全投球データ.csv>`: 「打席」を30列目から22列目へ移し、投手名の表記ゆれと球種の付け替えを直す
  - `make_base_pptx.py <型pptx> <出力pptx> <試合一覧.json>`: 作戦等のPPTX（表紙・分析対象試合・作戦）。型は `templates/作戦等型_日本生命.pptx`
  - `run_pitcher.py <全投球データ.csv> <作戦等pptx> <出力先>`: 集計 → グラフ → コメント草案 → PPTX。草案でコメントを上書きする
  - `build_pitcher_pptx.py <作戦等pptx> <stats> <charts> <comments> <出力pptx>`: コメントを直したあとはこれだけを流す
  - `analyze_pitchers.py` の `SPEED_RANGE`・`PITCHER_SPEED_RANGE`・`PITCHER_EXCLUDE_PITCH`・`UNKNOWN_PITCH`: 集計から外す球の決まり
- コメント: `output/pitcher/comments/<番号>_<名前>.md`。資料に入るのは「## まとめ」「## 対右打者 カウントコメント」「## 対右打者 投球図コメント」「## 対左打者 …」の2つと、任意の「## 投げ方」「## 防御率」
- 例: `~/大阪ガス/東海理化対策資料/`（BASS元のCSV、修正リスト、試合一覧のJSON、作戦等のPPTX、`output/pitcher/`）
- BASSの元データには試合番号の列がない。日付欄は入力日のことがあるので、画面で直せるようにする

## Proposed Changes

### Summary of Changes

- `desk/osaka_pitcher.py`（新規）: BASS元の取り込み、データを直す候補づくりと実行、試合一覧と作戦の下書き、作戦等のPPTXづくり
- `desk/comments.py`: 大阪ガスの投手はコメントのMDを読み書きする（見出しの下だけを書き換え、ほかは残す）
- `desk/export.py`: 大阪ガスの投手対策を「草案から作る」「コメントを残して作り直す」に分ける。出力先は `output/pitcher`。草案から作るときは、今のコメントを `comments/_控え_<日時>/` に残す。PowerPointで開いているファイル（`~$` のファイルがある）は書き出し・PDF化を止める
- `desk/onboarding.py`: 手順の済み具合に投手対策の手順を足す。作る資料の選択を覚える
- `desk/ai.py`: 大阪ガスの投手の下書きを、資料の欄（まとめ・対右/対左のカウント・投球図）と日本生命の回の書き方に合わせる
- 画面: 案内の最初に作る資料の選択、投手対策の手順4つ、資料タブのボタン2つと確認、投手のコメント欄の欄の並び

## Design Decisions

1. **データを直すのはすばるが決める**: 候補（ふだんの球速帯から10km/h以上離れた球、背番号が同じで名前が途中までの表記ゆれ）を出し、チェックを付けたものだけを修正リストに書く。理由の文は下書きを出し、直せるようにする
2. **集計から外れる球は知らせるだけ**: `analyze_pitchers.py` の設定はほかのチームと共通のコードなので、アプリからは書き換えない。外れる球と、足すとよい設定を画面に出す
3. **試合一覧は下書きして直す**: 日付・相手・スコアはデータから下書きし、試合番号の日付・大会名・最終スコアはBASSや公式サイトで確かめて直す
4. **作戦の表は下書きして直す**: 相手の攻撃側のデータの「作戦」列から、作戦ごとに状況・カウント・仕掛けた選手を数えて下書きする。今年の試合に出ていない選手の名前は出さない
5. **コメントを守る**: 草案から作るときは確認を出し、今のコメントを控えに残す

## Implementation Notes

**Implemented:** 2026-10-10

計画どおり作った。計画からの変更点は次のとおり。

- 付け替え先は、球速の帯がいちばん近い球種ではなく、取り違えやすい球種の組み合わせ（カット↔スライダーなど）を先に考えるようにした。
  最初は池田のカットに「チェンジアップ」を勧めていた
- 作戦の表で、「バント構え|セーフティバント」をバントにも数えていたのを直した。構えだけの打席は企図に数えず、別に「構えだけ○打席」と出す。
  作戦の列が空の犠打はバントに足す。バントの成功率は犠打だけを成功とする（手作りの表に合わせた）
- 準備の途中で投手のデータが増えたとき、投手の画面で誰も選ばれない不具合を直した（野手の画面も同じ）
