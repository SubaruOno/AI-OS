# てくてくまち ゲーム層の追加(まちの事業・まちレベル・合成)

> 2026-09-24。すばるの「ゲームとして拡張したい、アイテム過多でやることがない」という
> 課題から。仮説→実装→検証→考察のループで進める。コードは `~/Projects/walk-town`、
> ブランチ `base/town-growth`。

## 課題の整理(9/24 の診断)

1. 出口が細い。小物の使い道が「置く」「あげる」だけで、どちらも1個ずつしか消費しない。
   入り口(歩数・毎日・願い・手紙・なかよし度)は毎日大量に供給する。
2. 自分で決める目標がない。手紙13通を消化したら「今日は何をしよう」がなくなる。
3. 街が受け身。住人は待っているだけで、街自体が何も欲しがらない。

## 仮説

**仮説1: 街と住人が小物をまとめて欲しがる「まちの事業」があれば、出口が太くなり、
目標が生まれ、街が能動的になる。**

- 事業はタグ指定で材料を要求する(例: 木3・休2)。タグなので小物を足せば自動で候補に入る。
- 材料は「街に置いていない予備」から出す。住人へのプレゼント(おてつだい)と材料を
  取り合うので、どちらに使うかの選択が生まれる。
- 完成すると「まちポイント」が増え、**まちレベル**が上がる。レベルで新しい事業が解放される。
- 事業は複数同時に出る。どれを先に建てるかの選択がある。

**仮説2: 余った同種の小物をまとめて上位の小物にできる「合成」があれば、重複に価値が出る。**

- 同種のcommonを3つ → uncommonを1つ、のようにレア度を上げる。絵は既存を使い回す。
- 事業より小さく、手元で完結する出口。

## 実装するもの

- `src/town/projects.ts` — 事業の定義(タグ要求・レベル・報酬)とロジック
- `app/projects.tsx` — まちのレベルと事業の一覧・建設の画面
- `src/town/craft.ts` — 合成のロジック
- まち画面のヘッダに「まち Lv」のチップ(建設できる事業があると印)
- 日誌・利用記録・CONTRACT の更新

## 検証

- `scripts/check.sh`(型・lint・小物ID)
- Python で供給と消費のバランスをシミュレーション
- シミュレーターは前回つまずいたため、まずロジックとビルドで確かめる

## 決めた数字

- まちポイントのしきい値: 0 / 1 / 5 / 10 / 15 / 21(累計より低くして、事業を飛ばせる余地を残す)
- レベル名: はじまりの村 → 小さな村 → にぎわう村 → 湖の町 → 大きな町 → 湖の都
- 事業1件のポイント: 1〜4、全10事業で合計25pt(全事業の材料は計51個)
- 合成: 同じ小物の予備3つ → 次のレア度1つ(未所持3倍)

## 検証で分かったこと

- 最初のしきい値(0/3/8/15/24/36)は **詰み**だった。Lv1の事業2件で2点しか出ず、Lv2の3点に届かない。sim_projects.py が検出。
- 修正後: 2包み/日でLv6まで約22日、3包み/日で約15日。妥当。
- 合成は30日で5〜10回。主な出口は事業で、合成は補助。合成を主力にするなら「同じタグ3つ」等への変更が候補。
- シミュレーターで建設・レベルアップ・解放・合成まで動作確認済み。
