# U-23スタッフ共有サイト 第2版の計画

2026年10月16日。対象は [build_site.py](../apps/wbsc-collect/build_site.py) で作り、Cloudflare Pages に
上げている U-23W杯2026のスタッフ共有サイト。説明は [wbsc-collect](../docs/wbsc-collect.md)。

すばるが選んだ範囲は、見た目と中身の4つ（日本代表ページ、トップと日程・順位表、スマホの見やすさ、
相手国の今大会情報）と、大会への備えの2つ（更新の1コマンド化、電波が弱くても読める）。
点検で見つかった数字の誤りは、選択に関係なく直す。

## 決めたこと

- 時刻は**日本時間を先に太字**で出し、現地時刻を小さく添える。全ページでそろえる。
  日程の日付見出しは日本の日付でまとめ、「11/7(土)　現地 11/6(金)」の形にする
  （現地10:30〜19:30の試合は、日本時間ではすべて翌日の01:30〜10:30に入るので、日付が割れない）。
  「今日の試合」だけは現地の日付で選び、見出しに「現地 11/8(日)」と書く。
- URL はフォルダ形式にする（`team/cuba/` → `team/cuba/index.html`）。Cloudflare Pages が `.html` を
  拡張子なしへ308で転送しているため。入口の `<token>/index.html` は今までどおり開ける。
- 日本代表の元データは、公式発表を写した
  `~/野球/U23ワールドカップ2026/07_出場選手情報/サイト用/日本代表_公式発表.csv`（10/16に公式ページと照合済み）。
  手元の xlsx は使わない（背番号が所属チームの番号）。
- 手で整えたデータは `~/野球/U23ワールドカップ2026/07_出場選手情報/サイト用/` に置き、リポジトリには入れない。
- 生年から見て今大会に出られない選手（2002年以前の生まれ）の選手ページは作らない。表には残すが、名前はリンクにしない。

## サイトに載せないもの

リンクが漏れれば相手にも渡るものとして扱う。次は載せない。

- 便名、乗り継ぎ地での宿泊、宿舎名、JTBなど手配の担当者と連絡先、パスポートやESTAの話
- 公表されていないスタッフの名簿、どの人の連絡先も
- 選考合宿の測定値（BLAST・ラプソードなど）、日本の選手の生年月日・出身校、体調や起用の考え
- 配球の狙いなどの作戦。相手国のページは事実と公開データまで
- キューバの選手の身の上の情報（米国在住、契約の経緯など）
- 公表されていない練習試合の相手と時刻（公式に出ているのは 10/31 15時〜練習、11/1 13時〜 NTT東日本戦、11/2 は未定）

外部リンクで参照元を送らない設定（`no-referrer` と `_headers` の `Referrer-Policy`）は外さない。合言葉が漏れるため。

## ファイルの分担と、つなぎ目

並行で作業するので、1つのファイルは1人だけが書く。

### collect.py（データ担当）

- 裏の攻撃は raw で `"bot"`。`block.get("bot") or block.get("bottom")` で読み、`half` 列には `bot` と書く。
- raw を使い回すのは、保存済みの試合が終了（`gamestatustext` が `F` で始まる）で、`boxScore` が空でないときだけ。
  それ以外は取り直し、終わっていない試合は raw に保存しない。1秒待ち（SLEEP_SECONDS）は残す。
- `batting.csv` / `pitching.csv` / `plays.csv` の `date` 列が空なら、games.json の `start` の現地日付（`YYYY-MM-DD`）で埋める。
- 試合前に保存した `u23-wc-2026/raw` の30件は `/usr/bin/trash` でゴミ箱へ（`rm` は使わない）。

### build_report.py（データ担当）

関数名と引数はこのまま保つ（`read_csv`, `number`, `name_of`, `rate`, `batted_balls`, `collect_batters`,
`collect_pitchers`, `team_tendency`, `spray_chart`, `table`, `BAT_COLUMNS`, `PIT_COLUMNS`, `OPPONENTS`,
`EVENT_LABEL`, `DATA_ROOT`, `HIT_TYPE`）。引数を足すときは省略できる形にする。

- 出塁率の分母は 打数＋四球＋死球＋**犠飛**（`sf`）。打者の行に「犠飛」を足す。
- 引っ張り・流しは打者の左右で判定する。左打ちは右方向が引っ張り。両打ちは相手投手の投げ手の逆の打席と見なす。
  左右が分からない打者は数えない。
- 投球回は野球の表記（9回1/3 → `9.1`）で出す。この表記は数値として並べても順番が崩れない。
- 打球図は全図で同じ縮尺にし、距離の目安線を引く。±45°の外と距離0以下は描かない。点を大きくし、
  形でも種類を分ける（ゴロ●・ライナー▲・フライ■・ポップ◆など）。色はクラス（`spray-field` など）で付け、
  サイト側のCSS変数でダークとライトを切り替えられるようにする。単体レポートでも見えるよう、既定の色も持たせる。

### site_logic.py（新規・計算担当）

画面を持たない計算だけの部品。build_report からは `read_csv` と `number` だけを使う。

```python
def is_final(game) -> bool                      # gamestatustext が "F" で始まる
def game_state(game) -> str                     # "pre" | "live" | "final" | "other"
def local_dt(game) -> datetime | None           # 現地（UTC-6、夏時間なし）
def jst_dt(game) -> datetime | None             # 日本時間 = 現地 + 15時間
def standings(games, groups, round_label="Opening Round") -> dict[str, list[dict]]
    # groups: {チーム名(WBSCの英語表記): "A" | "B"}
    # 行: team, rank(int|None。試合がなければNone), g, w, l, t, pct("1.000" / ".667" / "-"),
    #     gb("-" / "1.0"), rs, ra, tqb(float|None), note
    # 並べ方: 勝率 → 2チーム同率なら直接対決 → 3チーム以上なら当該チーム同士のTQB。同率は同じ順位
def second_round(games, groups) -> dict
    # {"ready": bool, "super": [行...], "placement": [行...]}
    # 1次ラウンドの上位3・下位3を決め、当該チーム同士の1次ラウンドの結果を持ち越して数える
def japan_view(game, japan="Japan") -> dict | None
    # {"opponent", "batting": "先攻"|"後攻", "mark": "○"|"●"|"△"|"", "score": "5-3"(日本側から)|"", "state"}
def pitcher_log(pitching_rows, games, team, today=None) -> list[dict]
    # 投手ごと: name, _id, apps=[{date, gameid, opponent, gs, ip("6.1"), pitches}], last_date, rest_days,
    # total_pitches, gs_count。日付は gameid から games.json の start を引く（CSVの date 列に頼らない）
def person_key(name, birth_year, team) -> str   # 大会ごとに違う playerid を1人にまとめる鍵
```

`python3 site_logic.py --selftest` で、2022年と2024年の games.json から作った順位と持ち越し込みの順位が、
公式の結果と合うことを確かめる。

### site_offline.py（新規・電波担当）と update_site.sh, deploy_site.sh

```python
def head_tags(root: str) -> str     # root はそのページからサイトの根元への相対パス（"" や "../../"）
def body_end(root: str) -> str      # Service Worker の登録、status.js の読み込み、帯の表示
def write_assets(site_dir, core_urls, all_urls, version, status) -> None
    # sw.js, manifest.webmanifest, アイコン, offline/index.html, status.js, pages.json を書く
def headers_rules(token: str) -> str   # _headers に足す行（status.js と sw.js を毎回確かめさせる）
```

- 各ページはヘッダーのすぐ下に `<div id="band"></div>` を置く。`status.js` は `window.U23_STATUS` に
  最終更新（UTC）、結果を反映した最後の試合、版を入れる。帯には「最終更新 日本○／現地○・結果反映 ○まで」を出し、
  オフライン時や保存版を出しているときは「電波がないため ○時点の内容を表示中」、新しい版があれば
  「新しい更新があります（押すと再読み込み）」を同じ帯に出す。
- 読み込みは「3秒待って応答がなければ保存版を出し、裏で新しい版を取る」。保存は `r.ok` のときだけ。
  キャッシュ名は版ごとに変え、古いものは消す。最初に開いたときに `core_urls`（トップ・日程・相手国一覧・
  相手国11ページ・日本・大会方式）を先に保存する。保存のないページを開いたら `offline/` を出す。
- トップの `<button id="save-all">` を押すと `pages.json` の全ページを保存する（進み具合を出す）。
- ホーム画面に追加できるよう manifest・アイコン・theme-color を付ける。
- `update_site.sh`：取り込み → `build_site.py --out dist.new` → 検査（ページ数が減っていない、終了試合が減っていない、
  トップに「日本戦」がある）→ `dist` を `dist.prev` に、`dist.new` を `dist` に → 公開 → グループに貼る1行を表示。
  `--rollback` で `dist.prev` を上げ直す。`--no-deploy` で公開せずに止める。`set -e`。
- `deploy_site.sh` は公開するフォルダを引数で受けられるようにする（省略時は今の dist）。

### build_site.py（組み立て担当。上の部品がそろってから）

- 引数: `--out DIR`（既定は今の dist）、`--data-root DIR`（試し用。build_report の DATA_ROOT も差し替える）、`--new-token`。
- ページ: トップ、`schedule/`、`teams/`、`team/<slug>/`、`japan/`、`format/`（大会方式）、`p/<鍵>/`。
- ヘッダー: 日本・日程・相手国・大会方式。高さ44px以上、いま見ているページを強調。
- テスト用に、URLの `?now=2026-11-08T12:00:00-06:00` で「今」を差し替えられるようにする（カウントダウンと今日の試合）。

## 確かめ方

- 2024年大会のデータで、順位・持ち越し・勝敗の表示・登板記録を確かめる。
- 2026年の日程に2024年の結果をはめたダミーで、大会中の表示（試合中・終了・スーパーラウンド）を確かめる。
- スマホ縦 → 横 → 縦、PC、ダークモードで画面を見る。最後に iPhone のシミュレーターの Safari で見る。
- オフライン（ネットを切った状態）で、保存したページと保存していないページの両方を開く。
- 公開は、すばるが画面を見て了承してから。
